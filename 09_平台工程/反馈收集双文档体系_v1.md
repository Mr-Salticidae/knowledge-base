# 反馈收集的双文档体系：自由格式 + 结构化追踪

> 适用场景：需要让非技术测试者提交反馈，同时团队需要结构化追踪处理状态。

## 问题

传统做法是只给一份表格让测试者填——字段多、分类细，测试者打开就劝退。但如果只给一份自由格式文档，团队需要手动二次整理，效率低且容易漏。

## 方案：两份文档 + 双向链接

### 文档 1：反馈墙（面向测试者）

- **类型**：在线智能文档（smartpage），自由格式
- **权限**：所有人可编辑
- **内容**：
  - 顶部说明「随便写，不用管格式」+ 可选模板
  - 明确告知团队会转录到跟踪表
  - 放置跟踪表链接，测试者可查看处理进度
- **关键设计**：「可选模板」降低完全不知道写什么的心理门槛，但不强制使用

### 文档 2：跟踪表（面向团队）

- **类型**：智能表格（smartsheet），10 字段
- **字段设计**：
  - 反馈人（文本）
  - 反馈时间（日期，自动填充）
  - 反馈类型（单选：Bug / 建议 / 体验问题）
  - 严重程度（单选：P0 致命 / P1 严重 / P2 一般 / P3 建议）
  - 问题摘要（文本）
  - 问题描述（文本）
  - 复现步骤（文本）
  - 截图（图片）
  - 反馈状态（单选：新反馈 → 已确认 → 处理中 → 已修复 → 已关闭）
  - 备注（文本）
- **权限**：所有人可编辑
- **关键设计**：「反馈状态」字段让处理进度可视化，测试者也可以看

### 双向链接

- 反馈墙顶部 → 跟踪表：「你的反馈会被转录到这里」
- 跟踪表备注字段 → 反馈墙：「来源：反馈墙 URL」

## 工作流

```
测试者在反馈墙自由写
→ 团队定期收割新内容
→ 人工转录到跟踪表（分类、分级、标状态）
→ 按严重程度排优先级，启动修复
→ 修复后更新跟踪表的「反馈状态」为「已修复」
→ 测试者通过反馈墙顶部的链接看到处理进度
```

## 增量改进方向

如果反馈量上来了（20+ 条），人工转录会成为瓶颈。可以用脚本做预提取——正则匹配模板字段（【发现人】【问题】等）→ 调用 smartsheet API 自动录入，人工只做审核修正。
