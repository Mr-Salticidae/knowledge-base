# 新工作电脑 AIGC 环境从零搭建：单域名分流失败与 12GB 跑 33B 视频模型

## 一句话

**新机器装环境，真正的阻塞几乎都不在软件本身，而在「看起来能用」的网络和系统前提上：代理整体正常但单个域名走错线、Windows 显示的文件大小是假的 0、官方的断点续传在动态包上不生效——每一处都要换一个能分层的信号去测，而不是重试。**

## 过程回顾

1. **盘点** → 显卡驱动在、其余全空、无 winget；GPU 显存 WMI 读成 4GB（32 位截断），以 `nvidia-smi` 的 12288MiB 为准。
2. **工具链** → Scoop 拒绝管理员身份（`-RunAsAdmin` 解决），随后所有 GitHub Release 下载 TLS 握手失败 → 改用 npmmirror 镜像下官方二进制，验签/验哈希后装到 `<工作区>\tools\`。Python 静默安装在管理员身份下单用户模式失败（`0x80070003`），改 `InstallAllUsers=1` 成功。
3. **ComfyUI** → 依赖全装上，但 `import torch` 报 `c10.dll` WinError 1114：全新 Windows 缺 VC++ 2015-2022 运行库，装上即好。
4. **知识库** → `git clone` 37KB/s 后卡死；镜像站同样 31KB/s；codeload 打包 135KB/s 但断点续传失败。作者提示「YouTube 正常」→ 逐域名对照定位到 `github.com` 单域名失败 → 代理切全局模式后 1 秒内 200，clone 秒级完成。
5. **模型** → HuggingFace 走代理约 50MB/s；SDXL 6.5GB + Flux 16GB 几分钟下完。
6. **MiniMax H3** → 官方 BF16 单文件 62GB、示例 4 卡；选社区 GGUF Q4_0（10.6GB）+ 官方 NVFP4 文本编码器（14.6GB）+ 视频/音频 VAE + 4 步加速 LoRA，合计约 32GB；ComfyUI 已内置 H3 节点，只补 ComfyUI-GGUF 插件。
7. **Skill** → 按 [[SKILL_INDEX]] 路径约定用目录联接装载，联接按 frontmatter `name` 命名。

## 可复用 insight

### 1. 代理「整体正常」不等于每个域名都通：同一端口逐域名对照 ⚠️首次

**核心**：同一个代理端口、同一时刻，YouTube / Google / HuggingFace / `api.github.com` / `codeload.github.com` 全部 1 秒内 200，**唯独 `github.com` 5/5 失败**（CONNECT 返回 200，随后 TLS 握手被断）。直连 `github.com` 也不通。切全局模式后立刻 3/3 成功。

**来源**：前半天按「VPN 慢」处理——换镜像、重试、浅克隆，全部无效；作者一句「我看 YouTube 网速是正常的」把问题从「线路慢」改写成「分流错」。

**判据**：

- 用 `curl -x <代理端口> -w "%{http_code} %{time_appconnect}"` 对**同一服务的多个子域**逐个打。只有一个子域失败 → 是规则/嗅探层的问题，不是线路问题。
- 按 IP 连（`--connect-to github.com:443:<IP>:443`）仍失败 → 规则按 TLS SNI 匹配（mihomo 嗅探），换 IP 绕不过去。
- 规则模式下的修复在客户端侧：切全局 / 换策略组节点 / 开 External Controller 查命中规则。**下载侧的一切花样（镜像、续传、浅克隆）都是在错误层面用力。**

**边界**：本次没有拿到 External Controller 的命中记录（默认关闭），「被分到哪条规则」是推断，不是实证。

**与已有文档的关系**：[[ping通不等于路通_fake-ip假信号与节点带宽实测选型_v1]] 讲的是「永远绿的信号没用」，本条是同族的另一面——**「整体绿」掩盖了「局部红」**，要把测量粒度降到单域名。

### 2. Windows 上正在写入的文件，资源管理器/`Get-Item` 显示的大小不可信 ⚠️首次

**核心**：两个 curl 下载进程运行了 80 秒，目录里文件长度一直是 0；改读进程的 `WriteTransferCount`（`Get-CimInstance Win32_Process`）发现已写入 6.69GB、50MB/s。NTFS 目录项的大小在句柄关闭前不一定更新。

**操作规则**：判断「下载有没有在动」看进程 IO 计数或 curl 自己的进度，不看文件大小。差点因此误判为「下载卡死」而杀掉正常任务。

### 3. 断点续传要先确认对端支持 Range：动态打包的归档不支持 ⚠️首次

**核心**：`codeload.github.com/.../zip/HEAD` 是动态生成的 zip，`curl -C -` 直接退出码 33（服务器不支持 Range）。`git clone` 本身也不能续传。

**操作规则**：大文件续传只对静态对象成立（HuggingFace 的 LFS/xet 对象支持 Range，本次实测可续）；动态打包、git 协议传输都只能整包重来——慢线路上应先修线路，而不是寄希望于续传。

### 4. 全新 Windows 跑 PyTorch 的第一个坑是 VC++ 运行库 ⚠️首次

**核心**：`torch` 与 ComfyUI 依赖全部 `Successfully installed`，验证时 `import torch` 才报 `OSError: [WinError 1114] ... c10.dll`。根因是缺 VC++ 2015-2022 x64 运行库（安装返回 3010 = 成功、建议重启，不重启也能用）。

**操作规则**：装 Python AI 栈的验收不是「pip 成功」，而是 `import torch; torch.cuda.is_available()` 加一次 GPU 矩阵乘。新机器上把 VC++ 运行库列入前置清单。

### 5. 以内置 Administrator 身份运行时，安装器的默认路径会走歪 ⚠️首次

**核心**：同一台机器上两类安装器因管理员身份失败：Scoop 主动拒绝（需显式 `-RunAsAdmin`）；Python 官方安装器 `InstallAllUsers=0` 报 `0x80070003`，改 `InstallAllUsers=1` 成功。

**与已有文档的关系**：与 [[UAC关闭导致提权入口消失_内置Administrator与EnableLUA=0双重归因_v1]] 同属「内置 Administrator 改变软件默认行为」，本次是安装器侧的表现。

### 6. 12GB 显卡跑 33B 视频模型：量化主模型 + 加速 LoRA，验收看实测不看估算 ⚠️首次

**核心**：MiniMax H3 在 RTX 3080 12GB + 32GB 内存上可用的组合是 FL2VA Q4_0 GGUF + NVFP4 文本编码器（Ampere 上由 ComfyUI 转换运行）+ 4 步 turbo LoRA。实测 2.3 秒片段：20 步 171 秒 → 4 步 44 秒，画面结构无崩坏，turbo 版色彩更饱和、对比更强。

**操作规则**：

- 选量化档以「单文件 ≤ 显存」为起点（Q4_0 10.6GB 对 12GB），多参考模式（Ref2VA）在 12GB 上先不装。
- LoRA 接法以 ComfyUI 内置模板为准（`comfyui_workflow_templates_json` 里的 `video_minimax_h3_t2v.json`）：`LoraLoaderModelOnly` 强度 1.0，采样器/调度器不动，只降步数。
- 估算（「5 秒约 2 分钟」）只是推算，要单独实测后再写进 SOP。

### 7. 读含凭据的配置文件，别让报错把原文回显出来 ⚠️首次

**核心**：为定位代理问题读取客户端配置时，脚本本意是「列出键名、敏感值打码」，但 `ConvertFrom-Json` 解析失败，PowerShell 的报错信息把整份原文（含登录令牌）打印进了会话。打码逻辑在解析之后，解析一失败就形同虚设。

**操作规则**：对可能含凭据的文件，先用 `Select-String` 只匹配键名、或在 `try/catch` 里吞掉原始异常文本；不要让「解析失败」的路径能看到原文。事后处置：告知作者，由作者在客户端退出重登使令牌失效。
