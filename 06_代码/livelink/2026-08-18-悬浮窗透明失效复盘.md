# LiveLink 弹幕悬浮窗透明失效复盘（v1.8.1）

> 项目：LiveLink（Electron 31 弹幕助手，github.com/Mr-Salticidae/livelink）
> 日期：2026-08-18 · 提交：6e5d2ea

## 症状
弹幕悬浮窗的"背景透明度"滑杆怎么调都没效果，永远有一块深色底，做不到"背景全透只剩文字"。

## 根因
Electron 多页面入口（mainWindow / danmu-overlay 悬浮窗 / overlay OBS 页）共享了同一份全局 CSS。1.5.0 视觉系统重做时，把**不透明**的 body 背景（`--paper: #0d0c13` + radial-gradient 辉光）写进了 `tailwind.css` 的 `@layer base`。悬浮窗入口从 0.4.0 起就 `import '../renderer/styles/tailwind.css'`——当时无害（那份 CSS 没有 body 背景），1.5.0 之后悄悄变成"透明窗口杀手"。

三层透明叠加关系：`BrowserWindow transparent: true` → `index.html body transparent` → 组件 rgba 背景。body 上出现任何不透明背景都会把整窗填满，且叠在组件层之下，组件层的透明度参数全部失效。

## 定位方法
1. 写探针脚本用**与业务完全相同的窗口参数**创建窗口，`capturePage()` 检查角落像素 alpha——确认窗口透明本身没问题（排除 transparent+resizable 的老坑）。
2. 排除法收束到"页面一定有一层不透明底"→ 检查入口 import 链 → `main.ts → tailwind.css → @layer base body 背景`。
3. 用时间线钉死回归点：`git log -- src/danmu-overlay/main.ts`（0.4.0 引入 import）+ `git log -- src/renderer/styles/tailwind.css`（1.5.0 加 body 背景）。

## 修复
把 body 背景抽到 `shell-bg.css`，只让主窗口入口 import。悬浮窗 / OBS 页继续共享 tailwind（utilities 无害），但不再继承 body 背景。产物层验证：`out/renderer/assets/danmu-overlay-*.css` 中 0 处 radial-gradient、无 body 背景规则；asar 内同样确认。

## 通用教训
- **共享全局 CSS 的多入口 Electron 应用：`body`/`html` 级样式属于"入口私有"，绝不放进共享层。** 改全局样式时必须 grep 所有入口的 import 链。
- 透明窗口"调不透明"类 bug，先用最小探针（同参数窗口 + capturePage alpha）分流"窗口层问题"还是"页面层问题"，再查数据链。
- 沉默失败 = 产品 bug：TTS 在线合成失败只进 console，直播时表现为"失灵且无提示"。运行时错误要有计数 + 最近错误 + UI 警告条（5 分钟窗口，避免陈年错误吓人）。

## WorkBuddy 沙箱环境跑 Electron 的注意事项
- 会话默认 `ELECTRON_RUN_AS_NODE=1` → 必须 `env -u ELECTRON_RUN_AS_NODE`，否则 `require('electron')` 返回路径字符串。
- GPU 崩溃循环时加 `--no-sandbox --disable-gpu --in-process-gpu`。
- electron 二进制缺失：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js`。
- 探针进程记得 `Stop-Process -Name electron -Force`，否则锁住 `out/` 目录，electron-vite build 清理失败。
