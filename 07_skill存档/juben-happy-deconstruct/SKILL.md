# Juben Happy · 欢乐本过本单工作流

> 版本：**v1.1**（2026-11-19）· 新增「跨类型复用：换芯不换壳」、图表确定性承载与标注规范、正文口径字数判据
> **核心立场**：过本单是**执行单**，不是资料汇编。
> 它只有两个读者：坐在对面审你资质的平台，和站在台上只剩一只手能翻纸的自己。
> 判断标准极简单——**三分钟能读完，合上能开本**。读不完，就是写多了。

## 何时使用

- 拿到一个**无凶案 / 无搜证 / 无表决**的欢乐本、pia 戏本、互动本，要写开本单
- 拿到一个**资料包已完整**（手册 / 时间线 / 真相 / 线索表齐备）的硬核本，只需要出执行单 → **换芯复用七格**（见下节）
- 已经有一份很详细的资料包，需要收敛成一份可提交、可照单执行的文件
- 要在现场白板上画一张**玩家看得懂、自己画得完**的图
- 触发词里出现「过本单」「开本单」「交给平台」「欢乐本」

**不适用**：资料包还没拆完的硬核本 → 先走 `juben-deconstruct` 的八阶段流水线，拆完再回到本 skill 出执行单。**拆解归老匠，成形归本模。**

## 与 juben-deconstruct 的分工

| 环节 | 走谁 |
| --- | --- |
| 扫描件 OCR、拼版重排、音视频转写、资料去重 | `juben-deconstruct` 的 tools 与版面探测决策树 |
| 硬核本的真相萃取、时间线还原、四重层序判定 | `juben-deconstruct` 的复盘方法（本 skill 只消费结论，不重新推演） |
| 剧透三分级、对外文档去 PM 化 | `juben-deconstruct` 的对应章节 |
| **成品形态（过本单七格、白板、关系图、审核口径）** | **本 skill** |

一句话：**转写归老匠，成形归本模。**

## 七格模具（固定顺序，不许加格）

| # | 格 | 写什么 | 不写什么 | 体量上限 |
| --- | --- | --- | --- | --- |
| ① | 剧本信息汇总 | 类型 / 人数 / 时长 / 难度 / 玩什么 / 适合谁 / **不适合谁** | 出品故事、作者寄语、卖点文案 | 一张表 · 8 行 |
| ② | 人物关系图 | 一张图（坐标绘制，SVG / PNG）+ 5 行关系表 + 一句「这张图在本作为什么不寻常」 | ASCII 图、亲属树逐条展开、每人的秘密 | 图 + 12 行 |
| ③ | 故事复盘 | 一句话 → 反转层表 → 表层 / 中层 / 深层 → 关键动作全表 → 结局 | 逐幕剧情复述、台词摘抄 | **全文 40–50%** |
| ④ | 人物表 | 每角色**一句话**定位 + 一句分本卖点（可选） | 演员表、戏份星级、难度星级、道具列 | 6–8 行 |
| ⑤ | 带本流程 | **一条编号串**：①…㉗，每步带分钟数；末尾 3 条「必须管住的地方」 | 每步的操作细节、逐字话术、BGM 清单 | 1 段 + 5 行 |
| ⑥ | 机制 | **3–5 条**最核心规则，每条写「谁 · 何时 · 守什么 · 怎么判」 | 完整规则书、全部卡表、软件操作步骤 | ≤ 每格 8 行 |
| ⑦ | 会员 | 固定一句：大家是要走 128 的美团支付还是会员 19.9 呢？ | 任何解释、任何变体 | 1 行 |

> 第 ⑦ 格是门店话术，不是内容。**原样照抄，不要展开**。

## 跨类型复用：换芯不换壳

七格描述的是「开本要执行什么」，不是「这是什么类型的本」——它同时承担平台备案格式、台上翻页的肌肉记忆、跨本对比基准，三者都与题材无关。所以硬核推理本也能套，**只换第 ③、⑥ 格的内容**。

**三个前提**（缺一不做）：资料包已完整；只缺执行单；体例需与库内已定版一致。

| # | 格 | 欢乐本装什么 | 硬核本换成什么 | 动作 |
| --- | --- | --- | --- | --- |
| ① | 信息汇总 | 欢乐 / 无凶案 | 硬核 / 难度 ★★★★★ / 写清「不玩什么」「不适合谁」 | 换字段 |
| ② | 关系图 | 加害网、债务网 | **旧账网**：同一人多名、旧案凶手、六席与死者的错位 | 换内容 |
| ③ | 故事复盘 | 加害网 + 三层落差 | **四重反转表**（每重标「被哪条线索推翻」）+ 命案分层 + 关键动作全表 | **换芯** |
| ④ | 人物表 | 定位 + 分本卖点 | 定位含**动机与手法关键词** + 分本提示（谁拿凶手卡） | 微调 |
| ⑤ | 带本流程 | 编号串 + 3 红线 | 同结构，关键节点打 🔴，补 AP 口诀 | 加固 |
| ⑥ | 机制 | 敬酒 / 涨粉 / 换角 | 搜证 AP 递减（4→4→3）、处决与平票、定版时机、结局判定 | **换芯** |
| ⑦ | 会员 | 固定一句 | 同 | 原样 |

**硬核本特有红线（比欢乐本多五条）**：

1. 人数写死且注明**不可减人**——六席对应六条视角，减人即断链。
2. 时长闭合到官方区间内，给环节预算表，不只给总时长。
3. 反转层数 = 实际揭晓次数，每重标揭晓动作；少一层 DM 就会提前漏答案。
4. **逐重写白板、每重留讨论再翻下一重**——一口气讲完，高潮塌成念稿。
5. 写明「哪一步发什么牌、发几张、只发一次」——提前发，后两重直接失效且不可逆。

> 情感本未验证：情感本的复盘是情绪落点而非逻辑层序，第 ③ 格可能不适用反转表。机制本若机制本身构成叙事，第 ⑥ 格 3–5 条可能不够，需评估是否回到完整流水线。

## 收敛判据（本 skill 存在的理由）

欢乐本最容易写崩的方式不是漏，是**把「我知道的」当成「要用的」**。实测一版 9,400 字的过本单，被本人手删到七格后只剩六成——删掉的全是正确但当场用不上的东西。

| 判据 | 红线 |
| --- | --- |
| 总字数（正文口径） | ≤ 6,000 字，**不含**图片引用、图代码块、JSON、机器字段 |
| 故事复盘占比 | 40–50%（硬核本四重真相会顶到上沿，属正常），其余六格每格 ≤ 800 字 |
| 单格可读性 | 任何一格都能在一屏内看完 |
| 三分钟测试 | 平台审核员三分钟能判断「这本能开」 |
| 合上测试 | 自己合上文件，能凭编号串报完全场 |

> **正文口径**：DM 在台上不会去读关系图的 JSON 源码。图代码块、图片引用不计入正文、也不做占比分母——否则 6,000 的红线会被一张图冲垮，复盘占比被稀释到 40% 以下。
> **反向义务**：文档一旦声称「合上就能开本」（自包含），内嵌图片就必须**随仓库分发**——检查 `.gitignore` 是否把 `*.png` 全排除了，开一条精确到文件的例外。

**削的时候按这个顺序砍**（越靠前越先砍）：

1. 道具清单、BGM 编号、扫码操作步骤 → 挪进现场速查卡，不进过本单
2. 逐字台词、暖场话术、彩排提醒 → 手册里已有，过本单只留指针
3. 角色戏份 / 难度 / 道具三列 → 压成一句话
4. 机制的非核心分支（罚则细则、边界情况）→ 只留主规则
5. 结局的抒情段 → 保留最后一句金句即可

**永远不砍**：人数硬约束、时长闭合、反转层序、终本发放方式、必须强行收的节点。

## ③ 故事复盘怎么写（唯一允许长的部分）

欢乐本没有凶手，复盘的对象是**「观众以为在看什么」与「实际在发生什么」的落差**。四层模板：

1. **一句话**：谁、为了什么、把谁塞进了什么局、最后翻出什么。
2. **反转层表**：`层 | 玩家以为 | 实际 | 何时揭`。层数按揭晓顺序排，标出揭晓动作（喊「卡」、发终本、读尾声）。
3. **三层故事**：
   - 表层——玩家第一幕真的在演的那个故事（往往是个假案子）；
   - 中层——幕后真实规则（谁在拍戏 / 谁在设局 / 谁在发钱）；
   - 深层——终本揭的真身与真动机。
4. **关键动作全表**：谁对谁做了什么、用什么做的。欢乐本的「加害网」必须落到具体手段（盐、502、香蕉），否则主持人答不上玩家的随口一问。
5. **结局**：每个人的落点 + 最后一句留给玩家的话。

> 若这些动作构成闭环（A⇄B、A→B→C→A），**必须注明「彼此独立、没有共谋」**——闭环是事后看出的形状，不写清会被玩家当成团伙作案。

**硬核本改写**：同一格换成「一句话 → **四重反转表** → 命案分层（旧案 / 虚拟案 / 现实案）→ 关键动作全表 → 双结局」。反转表列头是 `重 | 玩家以为 | 实际 | 何时揭`，每一重都必须写「**被哪条线索推翻**」——不写，DM 就讲不清「玩家为什么该改主意」，现场只会变成念答案。

## ② 人物关系图（不要 ASCII，也不要交给引擎排）

- **必须出图**：SVG 手排 → HTML → 截图 / 打印。纯 md 表格看着累，评审也看不出结构。
- 欢乐本的常见陷阱：六个人本来就是一家人，**亲属树没有信息量**。图要画的是「谁害了谁」的加害网，或「谁欠谁」的债务网。
- 卡片三行足够：`名字 / 家庭位置·演谁 / 真身`。第三行标「第 N 幕前不许说」。
- 关系用「夫妻 / 情侣 / 父女 / 叔侄 / 闺蜜」这类**玩家听得懂**的词，不用「A 的 B 的 C」。
- 双重关系（既是女友又是闺蜜）单独用虚线绕行，别和主线挤在一起。

### 承载方式：顺序与位置是信息，就别外包给引擎

| 承载 | 失效方式 | 用不用 |
| --- | --- | --- |
| 私有 fence（`relation-graph` 等） | 渲染器不认 → **原样摊成源码**（实测 5,500 字符 JSON 铺满屏） | ❌ 只在确认同一套工具的封闭环境 |
| 通用引擎（Mermaid / Graphviz） | dagre 按入边分层：**无入边的节点被推到起始列**，分区顺序被打乱；改 `LR`/`TB` 只是换一种自动布局 | ⚠️ 结构对就行、位置无所谓的图 |
| **坐标绘制（Pillow / SVG 手排）** | 要自己算坐标、自己肉眼验收 | ✅ 有分区、有先后、有层级 |

**命中任一条 → 直接坐标画**：图里有分区且分区先后有含义；读者要按顺序读；要反复出图且每次必须一致；已经因「位置不对」返工过一次。

坐标绘制要点：分区先定 y 带再定 x；名字框宽度按实测文字宽度给（长名字单独加宽）；跨区连线走直角绕行、从节点底出底进，不穿别人的框；画布右侧底部各留 40px 给图例和注释。

### 标注规范四条（全部踩过）

| # | 规范 | 反面教材 |
| --- | --- | --- |
| 1 | 状态用**通用视觉惯例**：划掉、加粗、置灰 | `†`（dagger）在中文语境被读成十字架 |
| 2 | **不用西文符号承载中文语义**，已死就写「已死 / 已亡」或直接打红线 | 同上，且与「灰底＝已死」图例自相矛盾（该角色是金框） |
| 3 | 图例 ≥ 3 条一律**动态排版**（按 `textlength` 实测宽度推进），不用固定步进 | 固定 `x += 170`，长文案撞上下一个图例 |
| 4 | 分类编码 ≤ 2 种且不重叠 | 「灰底=死」「金框=玩家」「†=死」三重叠加，一个符号背两层信息 |

### 验收三步

1. **看最终载体**（PNG / PDF），不看源码；
2. **裁剪放大**局部：名字有没有溢出框、标签有没有压线、图例有没有重叠——缩略图看不出来；
3. **问一句「这个符号什么意思」**：需要图例才能懂的符号，就是没自解释。

现成脚本：`tools/relation_a4.py`（A4 横版 297×210mm，改 `P` 字典即可换本）。需要精确控制分区顺序时，按上述坐标法改写，不要退回 Mermaid 试参数。

## ⑤ 带本流程（一条编号串，不写操作手册）

同行互认的写法是**链式编号 + 括号分钟**，一眼能看出总时长是否闭合：

```
①背景介绍（3′）→ ②选角分本（2′）→ ③开场（3′）→ ④读第一幕 → ⑤…
```

- 时长必须**加起来等于总时长**，并在开头注明「本单按 N 分钟排」。
- 读本幕不标分钟，因为读本时长由玩家决定；标了反而误导。
- 串后只留 3 条「必须管住的地方」：哪一段要强行收、哪个动作不可当众做、哪一处省下的时间补到哪里。
- 手册里给了分段上限但加起来超总时长的，**按总时长硬分配**，并在串下注明压了哪一段。这是最容易翻车的地方。

## ⑥ 机制（3–5 条，一条一判据）

每条按四件事写：**谁 · 在什么时候 · 守什么规则 · 违反怎么判**。

欢乐本的机制通常只有三类，各取一条即可：

| 类型 | 典型形态 | 写清什么 |
| --- | --- | --- |
| 社交规矩 | 敬酒、称呼、座次 | 每人私知一条，凑齐才过关；只看主动方是否违规 |
| 分数驱动 | 粉丝数、积分、投票 | 加分节点全表 + 唯一一次减分点（用来告诉玩家分数会掉） |
| 角色流转 | 换角、抽卡、身份反转 | 顺序（谁先选）、时限、系统兜底 |

> **只在手机 / 小程序里记分，不手记**——手记必错，玩家当场对账。

**硬核本换成四类，各取一条**：

| 类型 | 写清什么 |
| --- | --- |
| 胜负判定 | 哪一方赢、死者是否仍可讨论投票、查自己尸体的时机 |
| 处决与平票 | 候选范围（谁已死不进候选）、每轮几人、平票后怎么走（发言重投 → 仍平则名额留空） |
| 搜证点数 | AP 递减（4→4→3）、每地上限、藏牌规则（藏新须公开旧）、哪些牌强制公开 |
| 规则 bug 与结局 | 哪两条规则是全本漏洞（玩家卡住先反问规则编号，不报答案）、结局按什么汇报内容分流 |

## 平台审核口径

| 要求 | 做法 |
| --- | --- |
| 不出现第二人称 | 全文无「你 / 您」；剧本原话必须保留时，放进引号并注明是台词 |
| 不出现内部术语 | 无本地路径、无脚本名、无「OCR / 转写 / 入库 / 仓库 / commit」 |
| 不出现物料缺口抱怨 | 缺件写成《开本前需确认》一条，不写成吐槽 |
| 剧透自持 | 过本单本身全剧透，**只交平台与主持人**；对玩家只发无剧透简介 |
| 可核验 | 人数、时长、幕次、页码写具体数字，不写「约」「若干」 |

> **别把「依赖」写成「缺口」**：二维码印在实体手册／玩家本上、BGM 与视频挂在小程序里、打印合本随盒自带——这些开箱即有。写进「开本前需确认」的只能是真缺的东西（自备道具、自印件）。判据是「先看载体」：找不到载体才是缺口，载体在盒内或在小程序里只是依赖。

## 白板（现场只带这一张）

- 板面 **4:3 横幅**，画布取 280×210mm，坐标手排，viewBox 单位 = mm。
- **六框 + 八箭 + 八个词，约 90 字**。超过 150 字现场一定写不完。
- 只写名词，不写句子；因果、理由、原句全部口述。
- 分次落笔：先立六框 → 玩家说一个连一条 → 最后一幕才补灰字（真身）。
- 现场脚本：`tools/board_4x3.py`（改 `NODES` / `edges()` 即可换本）。

**雷区（都踩过）**：

| 现象 | 原因 | 正解 |
| --- | --- | --- |
| 导出 PDF 后文字变成黑块 | `paint-order="stroke"` + 白描边在 `--print-to-pdf` 下不生效，描边按填充色画出 | 不用描边兜底，靠排版让标签不压线（标签统一放在自己那条线上方 3–4mm） |
| 符号变乱码 | `⇄`（U+21C4）在部分字体缺字形 | 写「与」，或用两支反向箭头分开画 |
| 全文件出现假 diff | `io.open(..., "w")` 在 Windows 把 `\n` 翻成 `\r\n` | 统一 `newline=""` 或二进制读写 |

## 交付三件套

| 产物 | 形态 | 去向 |
| --- | --- | --- |

## 检查清单

- [ ] 七格齐全、顺序未改、无第八格
- [ ] 总字数 ≤ 6,000（正文口径，结构化块不计）；复盘占 40–50%；每格一屏内看完
- [ ] 全文搜索「你」「您」→ 仅台词引号内命中
- [ ] 全文搜索路径、脚本名、「OCR / 入库 / 仓库」→ 0 命中
- [ ] 人数写死且注明能否反串 / 能否减人
- [ ] 编号串分钟数相加 = 声明总时长
- [ ] 反转层数 = 实际揭晓次数；每层标了揭晓动作与「被哪条线索推翻」
- [ ] 加害 / 互动动作落到具体手段，闭环处注明「无共谋」
- [ ] 人物表每人一句话，没有戏份 / 难度列
- [ ] 机制 ≤ 5 条，每条有判罚口径
- [ ] 白板 ≤ 120 字，PDF 已肉眼验收（不是只看 HTML）
- [ ] 关系图是图不是表，双重关系已单独处理
- [ ] 关系图**分区顺序成立**（主干在前、外围在后），已看 PNG 不是看源码
- [ ] 图内**无生造符号**（†、自定义记号），状态全用划掉 / 加粗 / 置灰
- [ ] 图例 ≥ 3 条时按实测宽度排，放大看过不重叠
- [ ] 内嵌图片已随仓库跟踪（`.gitignore` 有例外），克隆后不断图
- [ ] 会员那句原样保留

## 实战样本

| 本 | 规格 | 收敛过程 | 结论 |
| --- | --- | --- | --- |
| 《草台班子》 | 6 人 / 190 分钟 / 无凶案 / 欢乐 pia 戏 | 首版 9,400 字含六格全部细节 → 本人手删至七格 | 删掉的是正确但当场用不上的：道具列、逐字话术、戏份星级、机制分支；复盘与反转层一字未动 |
| 《虚拟游戏》 | 6 人 / 420 分钟 / 硬核推理 / 四重真相 | 一次成稿 5,564 字，复盘 45.6%，七格未改，仅 ③⑥ 换芯 | 硬核本可复用七格；**内容一次成型，配图返工三轮** |

**第一本学到的**：第一稿写全是对的，**交出去之前必须再删一遍**。删的标准不是「准不准」，是「台上那一秒用不用得上」。

**第二本学到的**：**内容可以用清单验收，呈现必须肉眼验收。** 清单查得出「有没有七格、占比多少、有没有第二个你」，查不出「B 区跑到左边」「这个符号什么意思」「图例压在一起」。三次返工全部由人眼发现，零次由脚本报出——所以凡是要被人看的产物，验收必须有一道「看最终载体」的动作。

**第二本踩的三个坑**（别重犯）：

1. 沿用库内私有 fence → 预览器不认识，5,500 字符 JSON 铺满屏；
2. 交给 Mermaid 排 → dagre 把无入边的节点推到起始列，改 `LR`/`TB` 都只是换姿势；
3. 用 `†` 标已死 → 中文读者读成十字架，且与图例逻辑冲突。

三次都指向同一句：**当顺序和位置本身是信息时，别把布局决定权交给引擎，用坐标画。**
