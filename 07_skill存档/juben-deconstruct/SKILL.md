# Juben Deconstruct · 剧本拆解工作流

> **核心立场**：任务不是「把资料转成文字」，是**让一个人能独立带完全场**。
> 转写只是原料，交付物必须回答：人物是谁、时间线怎么走、真相几层、线索指向什么、主持时什么时候做什么、哪里会翻车。

## 何时使用

- 用户丢来一个剧本资料包，说「读一下 / 转成 md / 我想学 / 我要当 DM」
- 用户要**给别人**（同事、学生、协作者）做学习资料
- 用户想把一个本沉淀成可对比、可迭代的知识资产
- 与 `maieutic-skill` 配合：本 skill 负责**产出资料**，maieutic 负责**带着人学会**

## 八阶段流水线

| # | 阶段 | 关键动作 | 产出 |
| --- | --- | --- | --- |
| 1 | **盘点与去重** | 递归列文件、按扩展名分类、MD5 比对多份资料包，找出**唯一完整真源**；记录缺口（如手册说 35 张卡但只有 18 张图） | 文件清单 + 体积 + 去重结论 |
| 2 | **版面探测** | 判断文字层 / 扫描件 / 拼版结构；抽样测 OCR 质量与单页耗时后再定批量参数 | 决策表（见下） |
| 3 | **全量转写** | PDF 文字层直提；扫描件 OCR；图片 OCR；音视频抽音轨 ASR + 抽帧 OCR | 按资料分组的 md + `_raw/` 纯文本 |
| 4 | **阅读顺序校正** | 骑马订 2-up 拼版必须按印刷页重排；图片按**文件名中的数字**排序（不能字典序） | 顺序正确的 md，保留原序备份 |
| 5 | **知识重组** | 先读组织者手册（真相/流程/线索逻辑通常全在这里），再读角色本补第一视角任务，最后读线索卡 | 人物档案、时间线、真相、诡计、线索→结论表 |
| 6 | **剧透隔离**（对外必做） | 按 🟢无剧透 / 🟡主持须知 / 🔴全剧透 **分文件**，导读里写明「哪份可以给谁」 | 可直接转发的学习包 |
| 7 | **归纳卡片** | 五维归纳：结构 / 真相 / 诡计 / 线索 / 主持；填跨本对比矩阵 | `07_归纳卡片.md` |
| 8 | **入库与回填** | 剧透资料进**私有**仓库，方法论与工具进**公开**知识库；开本后回填现场翻车点 | commit + push + CHANGELOG |

## 版面探测决策树

| 情况 | 判据 | 处理 |
| --- | --- | --- |
| PDF 有文字层 | `pdftotext` 前两页能抽出非空白中文 | 直接提取，保留表格结构 |
| PDF 是扫描件 | 抽不出文字，但 `get_images` 有大图 | 渲染 → OCR |
| **骑马订 2-up 拼版** | 一张 A3 上左右两栏，页脚数字分别是 1 和 32、2 和 31 | 按中缝切栏 → 用页脚数字还原印刷页 1→N |
| 纯 JPG 扫描包 | 全是 5100×7014 之类高清单页 | 按目录分组、按数字排页序，OCR |
| **2×2 拼版线索卡** | 一张图上 4 个证据块，手册却说卡有 35 张 | 别按「图数=卡数」计数，OCR 全抓后按手册编号体系整理 |
| 音视频线索 | ffprobe 看时长与音轨 | 抽音轨 ASR **＋** 每 4 秒抽帧 OCR；纯视觉线索必须人工/多模态看图补 |

> **无声视频是最大的暗坑**：很多线索既无台词也无字幕，情报在「看见了什么」（如眼球泡在防腐液盒里、招牌写着十年老店）。只做 ASR 会漏掉官方点名的推理支点。

## 工具箱

脚本随 skill 放在 `tools/`，路径全部参数化，不写死盘符。

| 脚本 | 用途 | 典型调用 |
| --- | --- | --- |
| `scan_ocr_pipeline.py` | 纯 JPG/PNG 扫描包 → 分组 md；数字排序、行聚类还原段落、多进程 | `python tools/scan_ocr_pipeline.py --src <资料包> --out <输出> --workers 6` |
| `ocr_pipeline.py` | PDF 扫描件 → md；双栏切分、页脚识别；`JUBEN_SRC`/`JUBEN_OUT` | `JUBEN_SRC=... JUBEN_OUT=... python tools/ocr_pipeline.py --workers 6` |
| `reorder_imposition.py` | 骑马订 2-up → 印刷页顺序重排 | 在 OCR 产物目录上运行 |
| `text_docs.py` | PDF 文字层 / DOCX / TXT → 结构化 md | 同上环境变量 |
| `video_frame_ocr.py` | 视频抽帧 + 画面文字 OCR | `python tools/video_frame_ocr.py --src <视频目录> --out <md> --interval 4` |
| `AudioTranscribe` | 音频/视频台词转写（先 ffmpeg 抽 16k 单声道 mp3 更稳） | 逐文件调用 |

**环境**：`pymupdf pillow numpy onnxruntime rapidocr_onnxruntime python-docx pyyaml`；外部命令 `pdftotext` / `ffmpeg` / `ffprobe`。

**性能要点**：ONNX 推理必须**每进程单线程**（patch `SessionOptions.intra_op_num_threads=1`），多进程并行；否则线程争抢会让 300 页从 5 分钟拖到 20 分钟以上。缩放长边 2000px 是精度/速度平衡点。

## 三层知识结构（每个本都按这个落）

```
转写层  01_角色剧本 / 02_线索卡 / 03_开本资料 / _raw/   ← 可检索、可喂模型
应用层  00_DM主持学习手册 / 00_开本速查卡 / 对外学习包   ← 学会 + 带本
归纳层  07_归纳卡片 / 跨本对比矩阵                       ← 越学越省力
```

## 降低学本难度（每个本收尾必做 · 三本实战验证）

> **转写准确 ≠ 学得会。** DM 学本最大的障碍不是信息少，是**信息平铺、没有权重**：25 行流程表、十几处「必背」、两套四重解答表全压在同一层，新手会直接合上文档。
> 收尾时把「辞典」改造成「教材」，按下面六步做一次。**不增加文档数量**，只改现有应用层文档的结构。

| # | 动作 | 落地位置 |
| --- | --- | --- |
| 1 | **导航化**：把「读什么」改成「今晚 90 分钟怎么排」—— 分段计时 + 过关标志 + 最低开本线 + 放弃线 | 手册 §0 |
| 2 | **必背分级**：全篇「必背 / 必做 / 全本心脏」收敛成 **A 级 ≤5 条一句话锚点**；B 级逐字话术全赶进速查卡，正文只留指针 | 手册 §0.2 / 速查卡末节 |
| 3 | **每表前加「先记一句」**：规则表、谜面表、解答表各给一条能脱离表格独立成立的锚点 | 手册各表前 |
| 4 | **毁本红线可视化**：流程表给不可逆环节加 🔴，表后单列「错一步 / 后果」两列清单 | 手册流程表 / 速查卡流程块 |
| 5 | **验收后置 + 答案定位**：自测题不要放导语（一开篇就撞上未学术语），移到文末验收节，每题附「答案在哪一节」 | 手册末节 |
| 6 | **跨文档一致性复核**：手册 / 速查卡 / 时间线底稿里的时间、动作顺序、层序、「被什么推翻」必须口径一致；有异文时**指定流程表为唯一发放时刻基准**，其余注明「提前到点，非额外多发」 | 三份应用层文档 |

**专家小组交叉验收**（多重解答 / 设定诡计类必做）：并行派三路**只读**审阅，每路都要求引用具体章节号输出「问题 → 改法」，再统一落地：

| 角色 | 盯什么 |
| --- | --- |
| 资深 DM | 现场哪些话必须脱口而出、哪些动作不可逆毁本、急救梯度有没有兜底 |
| 首次学本新手 | 哪一节会想放弃、「必背」散落几处、术语密度、自测题放错位置没有 |
| 逻辑一致性校订 | 跨文档矛盾、年份时点、伪解口径误入「实际」列、线索错层、同一动作两种顺序 |

> 第三个本一次挑出 **13 处矛盾**，其中「伪解口径写进实际列」「立起本层的线索被写进『被什么推翻』」「同一动作两种顺序」最伤学本信心 —— 事实不一致比内容难更劝退。

**验收判据**：合上文档，一个新 DM 能否在 90 分钟内走过「规则关 / 流程关 / 真相关」，且**开本当天只带一张双面 A4**。做不到，就是又多写了一份辞典。

## 剧透隔离（对外交付的硬规则）

**必须做文件级隔离**，不要只在一篇文档里加「以下剧透」——转发出去就收不回。

| 标记 | 内容 | 可给谁 |
| --- | --- | --- |
| 🟢 | 导读、本作是什么、学习路径、无剧透自测 | 任何人，含准备上车的玩家 |
| 🟡 | 流程、发本题答案、线索发放规则、角色定位表 | 仅主持人 |
| 🔴 | 真相、时间线、诡计、排除法、音视频指向 | 主持人 / 已玩完想复盘者 |

导读里必须写一张「哪份可以给谁」的表，以及一句「不要把后面几册发给还没玩过的人」。

## 对外文档去 PM 化清单

给同事／学生／协作者的文档里，**以下一律不出现**：

- 本地绝对路径、盘符、`_raw/`、`~/.workbuddy/skills/` 等目录名
- 「OCR」「ASR」「转写」「抽取」「重排」「可信度 A/B/C/D」「来源文件」「rename mapping」等内部术语
- 「入库」「归档」「commit」「push」「仓库」「去重」「流水线」等项目管理词
- 任务编号、工具脚本名、报错日志、页码溯源标记

**替换说法**：想说明准确性，写「本文依据官方手册整理，个别字词以原册为准；涉及投票判定与编号时请与原册核对」。想说明视频线索，写「部分视频为纯画面线索，请回看原视频」，不要写「帧 OCR 未检出文字」。

> 内部索引（`cases/<本>/README.md`）才负责记录来源、体积、提取方式与可信度；两份文档各司其职，不要混成一份。

## 常见坑（三本实战验证）

1. **两份资料包不是互补而是副本**：MD5 全比对，选文件数更多的那个当唯一真源。
2. **人数陷阱**：剧本里出现「7 名玩家」不代表 7 人本，NPC 可能由 DM 扮演；以手册为准。
3. **线索编号两套体系**：「线索 32」可能指虚拟世界线索而非总表，勘误要对照手册读。
4. **同批卡的不同打印版**：A4 / B5 / 全尺寸三套别重复发。
5. **推理线程争抢**：见「性能要点」。
6. **中文路径**：用 PowerShell 直接传 Unicode 建目录联接，别写含非 ASCII 路径的 `.bat` / `.ps1` 脚本，编码会花。
7. **两包互补而非副本（反例）**：一个包只有手册、另一个只有玩家册；先比对**文件名全集**再决定要不要去重，别删任何一侧（LTC）。与上一条合看：默认动作是「先判断关系」，不是「直接去重」。
8. **官方点名的音视频物料不在包内**：手册写「发实拍视频 / 把音频发到群里」，资料包里却没有；入库单列「资料包缺口」清单，写明用途与获取方式（LTC 缺 4 样）。
9. **纯插图页**：一页只有一幅画、OCR 无文字；拼缩略图逐页核看，区分装饰页与叙事插画，把暗示人物设定的画面补进关系图（LTC 11 页）。
10. **人数陷阱变体**：剧本出现 8 个座位 / 8 个人名，DM 又占一个剧中身份；以手册「玩家为 N 人」为准，DM 与 NPC 单列。
11. **必背无权重**：全篇十几处「必背 / 必做 / 全本心脏」，新手直接合上文档；见「降低学本难度」。
12. **跨文档异文**：同一动作在手册 / 速查卡 / 时间线底稿里写成两种顺序、两个时长，甚至把伪解口径写进「实际」列；DM 会反复怀疑自己，比内容难更劝退。
13. **白板字数超载**：复刻了模板的形式却没复刻密度，推理过程与操作提醒全上板（曾做到模板的 2.3 倍）；见「白板演示密度」。
14. **有官方板书图却自创一套**：手册明明给了渐进板书，却按模板另画四区、把推理结论逐轮擦改上板，越压字数越拧巴；动手前先全文搜「参考板书 / 板书如下」（LTC 官方 6 张，印刷页 14/38/49/53/83/98）。见「白板演示密度」。

## 白板演示密度（现场写得下才算数）

白板是**给玩家看的索引**，不是给 DM 看的讲义。954 原版最终全貌 298 中文字 / 单行 ≤18 字 / 60 秒速抄 177 字，这是密度基准；只复刻结构、不复刻密度，会做出 2 倍字量的板，现场根本写不完。

**第 0 步：先找官方板书图（优先于一切密度技巧）**

复刻之前先全文搜组织者手册的「参考板书」「板书如下」「板书要点」「补充的参考板书」。官方若给了渐进板书，**以官方原图为唯一板面标准**，别再按模板自创四区：

1. 用 PDF 图像 bbox 精确裁出每张原图，按印刷页命名存档；仓库若忽略 `*.jpg`，必须补 `.gitignore` 例外，否则 clone 后图全丢。
2. 跟画卡底图直接内嵌原图（base64），只叠紫色框标「这一笔新增哪一块」；`whiteboard-trace` 五字段格式不变，viewer 无需改解析。
3. 正文只留：原图索引表（页码 / 时机 / 本笔补什么 / 文件名）、落笔节奏、易抄错处、60 秒速抄；推理轮次与结论回到 DM 手册，不上板。
4. 徽标别拿 SVG 里的 `<text>` 统计字数冒充「板上累计」——原图是位图，注明「以官方原图为准」。

LTC 实测：自创四区 12 笔 349 字、单笔峰值 66 字；官方 6 张原图每行 ≤9 字、左 1/4 全程留白、随玩家分享分次落笔，单次 ≤25 字。**写得下不靠缩写，靠照官方的分次与留白。**

**三不写**
1. 不写「为什么」：推理因果、推翻理由、官方原句由 DM 口述。
2. 不写操作提醒：「先放盘 15 分钟」「视频那一刻才播」属于速查卡 / A4。
3. 不写长句：每样只留 ≤16 字短标签（人名 / 编号 / 结论词）。

**做法**：生成脚本加缩写映射层，长句映射成短标签、不该上板的映射为空；被压缩 / 删除的原句挂成 SVG 注释，生成时自动回收进该笔 `画什么` 的「口述（不上板）」，**信息零丢失**。每笔标注 `✍ 板上写 N 字`，超过 45 字自动提示「分两次落笔」。删行后把成组内容收拢，别留孤行挂底；下半部留白明确写成「给现场补玩家推论」。

**量化判据**（无官方图、需按 954 形式复刻时，生成脚本必须断言）：最终全貌 ≤360 字、单行 ≤18 字、单笔落笔 ≤70 字、速抄版 ≤200 字。有官方板书图时不适用，以原图的分次落笔节奏为准。

**同步检查**：缩写后 `画什么` 说明与连线清单表注必须同步改，否则 DM 会照着旧说明去找已经撤下的行。

## 与 maieutic-skill 分工

| 阶段 | 用谁 |
| --- | --- |
