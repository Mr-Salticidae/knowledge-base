本仓库公开的是**方法论与代码样例**,不是素材包。文档中出现的 `{AIGC工作站}`、`项目工作区/` 等路径均为本地工作区占位,用于说明来源和上下文,不要求读者具备相同目录。

## 这是什么

每次创作探索后,把**有 insight 的发现**沉淀到这里,形成可复用的长期资产。

不是产出归档,**是 insight 归档**——
图、音频、视频等素材本身通常不在本仓库,这里只存"我学到了什么"。

本目录是一个 **Obsidian Vault**(配置见 `.obsidian/`)。所有文档之间用 `[[双链]]` 互相连接,既能点击跳转,也能在 Obsidian 的关系图谱里看到知识脉络。

## 怎么用这个知识库

1. **从这份 README 出发** —— 它本身就是入口地图(MOC, Map of Content),按主题串好所有文档
2. **按目录找** —— GitHub 浏览优先看 [[03_prompt模板库索引]] 和 [[04_方法论与洞察索引]],再进入子目录
3. **沿着 `[[双链]]` 跳** —— 每篇文档底部的"关联文档"段都是入口,顺着走能看到一整条思路
4. **按 `Ctrl+G` 看图谱** —— Obsidian 的关系图谱会直观显示哪些文档是中心、哪些是孤岛
5. **搜不到就建** —— 写新文档前先 `Ctrl+O` 模糊搜一遍,确认没有就建;能加补丁就别建新文件

### 主题脉络十:AI 理论与创作哲学(2026-05-29 新增子脉络)

> 外部理论 / 思辨型读书笔记。不是手把手的创作技巧,而是"底层机制 + 创作者定位"的认知反思。
> 颜色按 ⚫ `类型/协作工具链`(战略反思)涂——脉络是阅读视角,颜色是类型视角,二者可交叉。

- [[低频退化与频率定律]] —— 模型理解的是语言的**统计分布**;prompt 工程方向是"写得更高频"而非"写得更复杂",是 [[prompt极简化原则_v1]] 的理论解释
- ⭐ [[压缩保留簇丢弃孤例_v1]] —— 决定一样东西在模型里命运的是**簇密度(样本量×同质度)**,不是"冷门还是大众";倒 U 型坐标:大而散被均摊拉平 / **小而密是甜区**(载重风格词) / 低频实体表达退化 / **n=1 压不进去也无法从邻近重建**。把 [[冷门风格词的压缩律_v1]] 与 [[低频退化与频率定律]] 统一到单一变量上;推论"不可替代性=无簇性"呼应 [[真实摄影手段作为AI时代的稀缺性]]。含 Project Panama 实体书销毁事件事实核查(哪些坐实/哪些未证实)+ 用 [[伪机制解释识别_四层拆解法_v1]] 裁决凯文·凯利《潜空间》 ⚠️首次 · **❌同日被领域内人士实读证伪一个用法**:不能拿它宣判学科/职业存亡——把一门实践切成"可压缩层/不可压缩层"本身就是外部强加的整洁模型,正是本篇指控 KK 犯的那个错(**批判某种思维错误不使你免疫于它**);适用范围收窄到素材/表达/工序。另记一条本律装不下的东西:**积累型判断力**(由高冗余材料养成,却不随材料一起被压缩)
- [[生成时代作品作者版权重定义]] —— 作品=形式本体 / 作者=发现者+命名者 / 版权=调用权;复制成本归零后"被调用越多,原点价值越大"
- [[知识传播与知识付费边界]] —— 知识创造者应得到回报,但基础知识不应被付费墙垄断;AI 时代价值更适合落在服务、支持和公共机制上
- [[沉思录读书笔记_关系义务与自足之美]] —— 斯多葛读书笔记:忙碌不能取消对身边人的义务,赞美也不能决定事物自身的价值
- [[故事读书笔记_工具丰饶不等于创造力丰饶]] —— 麦基《故事》(1997)读书笔记:工具的丰饶≠创造力的丰饶;看过≠懂得,会用工具≠会创作;把"剧作家"换成"AI内容创作者"一字不用改,28年后依然成立
- [[对话感_关系产生生命力]] —— 单人叙事提供信息 / 双人叙事创造关系 / 多人叙事构建世界;作品一旦出现"关系"就有生命力,比起表达更重要的是回应(Suno 男女对唱偏离预设的意外发现)
- [[语言形式_思维模式_沟通成本]] —— 口语探索、结构文档、执行指令不是同一种语言形态;AI 工作流的价值在于把探索语言转译为可执行、可复用的语言流程
- [[沟通成本的第二来源_范围与高度错位]] —— 沟通成本还有第二来源:范围/高度错位;精密文档因边界缺失反而高成本,继承结构化产物前要先用负向规格逼出"不做什么"(bilibili-ctr 实战复盘)

### Frontmatter 写法

每篇新文档的**第一行起**这样写(注意 `---` 必须顶到文件最开头,YAML 之前不能有空行):

```markdown
---
tags: [类型/核心方法论]
---
# 文档标题

> 入档:2026-...
> 主线作品来源:...
```

### 怎么选颜色(决策树)

1. **是 sref 档案 / 参数实测档案吗?** → 🟠 `类型/档案`
2. **是可复用的 prompt 段或获奖图复盘?** → 🟢 `类型/prompt模板`
3. **是 IP 视觉系统 或 视频 / 配乐方法论?** → 🟣 `类型/IP视觉`
4. **是代码索引 / 代码项目说明?** → 🟤 `类型/代码`
5. **是 Claude Code / 协作 / 战略反思?** → ⚫ `类型/协作工具链`
6. **是角色一致性主线的金字塔级方法论?** → 🔴 `类型/核心方法论`
7. **其他风格 / 媒介 / 审美方法论** → 🔵 `类型/风格审美`(兜底类)

### 颜色与"主题脉络"的关系

上文 MOC 里的"主题脉络一~九"是**阅读视角**(按使用场景串),颜色是**视觉视角**(按文档类型一眼分类)。两者会有交叉:比如 [[图生视频_ForwardOnly原则]] 在 MOC 里归"视频/影像方法论",颜色按"IP视觉"涂(因为这条线主要服务 IP 视频出片)。这是正常的 —— 一个文档可以在 MOC 里出现多次,但**颜色标签只有一个**。

### 改类型 / 加新颜色

- 改类型:直接改 frontmatter 的 `tags`,Obsidian 重新索引后图谱颜色自动跟着变
- 加新颜色:本规范暂定 7 色封顶。如果将来开了新主线(如"抖音视频化战术"、"商业化"、"AI 编程工程化"等 AIGC 工作站新延展),先想能否归到现有 7 类。**真的需要新增**时,同步更新本表 + `.obsidian/graph.json` 的 `colorGroups[]`

### 多重标签(可选,不影响颜色)

颜色只看 `类型/xxx` 标签。你可以**额外**加二级标签做更细的检索,但颜色不变:

```yaml
---
tags: [类型/核心方法论, 主题/角色一致性, 来源/02_角色一致性锚点]
---
```

Obsidian 的 Tags 面板会按标签分组列出。`类型/` 是颜色轴,`主题/` 和 `来源/` 是辅助检索轴。

## 链接规范(写新文档必读)

### 1 · 每篇文档必须有"关联文档"段

放在文档末尾,**用 `[[]]` 双链语法**,不要写裸路径或 \`code\` 包裹的文件名(那样在 Obsidian 里点不开)。

**好的写法:**

```markdown
## 关联文档

- 顶层方法论:[[角色一致性金字塔]]
- 互补技巧:[[装扮签名vs五官精度]]、[[personalize与moodboard分工]]
- 主线作品:`{AIGC工作站}/03_StyleCreator暗调版\...`  ← 仓库外的产物可用裸路径
```

**不好的写法(老格式,Obsidian 点不开):**

```markdown
- 关联方法论:`04_方法论与洞察/01_角色一致性与视觉签名/角色一致性金字塔.md`
- 关联现象:`personalize与moodboard分工.md`
```

### 2 · `[[]]` 的几种写法

| 写法 | 效果 |
|---|---|
| `[[文件名]]` | 跳转到该文档 |
| `[[文件名\|显示文字]]` | 显示别的文字,点击同样跳转 |
| `[[文件名#二级标题]]` | 跳到该文档的某个标题 |
| `![[文件名]]` | **嵌入**该文档的全部内容到当前文档 |
| `[[文件名]]` 但目标不存在 | Obsidian 会标灰,点击可直接创建该文档 |

### 3 · 链接的方向(枢纽 + 卫星)

- **卫星 → 枢纽**:具体档案(sref 档案 / 复盘)在底部链回**顶层方法论**
- **枢纽 → 卫星**:顶层方法论列出**典型例证文档**
- **同层互链**:类似主题的方法论(如 [[AI甜妹脸vs复古东方美人]] 和 [[装扮签名vs五官精度]])互相链接

### 4 · 仓库外的引用保持裸路径

主线作品在 `{AIGC工作站}/` 别处时,继续用 \`{AIGC工作站}/xxx\\\` 这种裸路径写,不要硬塞 `[[]]`(Obsidian 链接只在 Vault 内有效)。

### 5 · 待写文档也可以先 `[[]]` 占位

```markdown
- 顶层工具:[[StyleCreator方法论]] ← 待写
```

Obsidian 会把它显示为灰色"未解析链接",点击就能直接创建,等于自动维护一份"待写清单"。

### 6 · 命名约定

- 文件名**不带 .md 后缀写在 `[[]]` 里**:正确 `[[角色一致性金字塔]]`,错误 `[[角色一致性金字塔.md]]`
- 文件名**不重名**:即使在不同子目录,文件名也保持全局唯一(Obsidian 双链按文件名解析,重名会冲突)
- 命名风格:**核心概念名 + 限定词**,例如 `seed_行为规律` / `personalize与moodboard分工` / `MJ审核避雷词表`
- **`README.md` 全库只能有一个**:就是当前这份根目录的 MOC。任何子目录想做"目录说明"的,文件名用 `{业务名}索引.md`(如 [[代码资产索引]])或 `{业务名}说明.md`(如 [[MV模板说明]])——这样 Obsidian 文件树里不会出现多个 README 同名节点,图谱里也不会出现"两个 README"的歧义
