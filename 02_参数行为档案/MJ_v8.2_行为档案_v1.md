## 实测行为（49 EP02 · 单项目样本）

### 1. 写实质感 ⚠️首次

老 prompt（半写实厚涂词系 `semi-realistic anime illustration style, painterly rendering`）直跑，出图质感即达"发丝级细节 + 真实皮肤过渡"，明显优于同 prompt 在旧版本的表现。**质感提升不挑词系**——连非写实词系都被拉高。

### 2. 异色瞳一句直给稳定命中 ⚠️首次（6/6，样本小）

```
one cold ice-blue eye and one warm rose-pink eye
```

- 写法要点：**左右 + 冷暖 + 具体色名**，不写抽象单词 heterochromia
- 单批 6/6 全中，预备的 `--no matching eye color, symmetrical eyes` 双保险未动用
- 边界：双眼均清晰可见的近景构图下验证；侧脸 / 遮挡构图未测
- 旧版本经验（异色瞳老大难、需负面词双保险 + 局部重绘兜底）在 v8.2 上**疑似过时**，待跨项目再验

### 3. sref 跨批质感续接 ⚠️首次

改 prompt 变量（本次改瞳色短语）时 sref 上一批成品图，新批与旧批**视觉无断裂**——"修 bug 不丢手感"。分工理解：sref 管质感氛围，不管脸的一致性（锁脸仍走 [[角色一致性金字塔]] 的描述锚定 / oref 路线）。

### 4. 非人像场景质感 ⚠️首次（闪电战单样本 · 2026-07-16）

「同根同源」闪电战《七步诗 · 空屋火影》：古代灶间写实场景（土墙颗粒 / 火光层次 / 蒸汽体积感 / 硬光影子）一版立住，写实底座直接撑起影子叙事的可信度。参数组合 `--ar 3:4 --preview --style raw` 可用（与本档案人像侧的 `--raw --hd` 并存，未见冲突）。影子形态指令 `shadows clearly shaped as ...` 命中但形态偏离（two little brothers → 一大一小身影），属「偏离即升级」。详见 [[2026-07-16_同根同源_七步诗空屋火影高票复盘]]。

### 5. 未测项（占坑）

- v8.2 是否支持 oref / cref（v8.1 不支持，见 [[MJ_v8.1_无oref_混合工作流]]）
- `--stylize` 响应曲线（正式版下重开，44_异常值 已挂测试，见下）
- 静物 / 特写题材的质感增益（场景已开测，见第 4 条）
- 正式版 `--v 8.2` 与 preview 通道产出是否等价（本档案第 1–4 条需复测）

### 6. 要图标不要字：`--no` 四词法 ⚠️首次（闪电战单样本 · 2026-08-06）

PB 闪电战「时间贫困」回转寿司图。需求矛盾：盘沿贴纸上要出现**抽象几何图标**，同时全画面零文字（日料店的招牌与菜单是高危背景）。

**有效写法**：

```
--no text, letters, words, numerals
```

- ⚠️ **`logo` 绝不能进 `--no`**——会把要保留的图标贴纸一起压掉。挡字形靠 `text / letters / words / numerals` 四个词就够
- 真品牌 logo 不点名就不会自己长出来，不需要负面词防守
- 正向侧配合：`a different small round printed sticker showing a simple flat abstract geometric app-icon mark, flat solid colours, no letters no words` + **列举 4–6 个具体形状**（spiral / hexagon / triangle / sail / circle with a dot / asterisk）

**结果**：全图零字形崩坏（含背景菜单区）；传送带盘沿的图标造型干净、彼此不重复，`every icon different from the last` 命中。

**结论**：**抽象几何图标是替代真品牌 logo 的可行路径**——MJ 画不出可识别的真 logo，只会给融化的伪字形，在同行互投场上是最扣分的元素（一眼「AI 做的」+ 白送破解感）。

**边界**：写 `each plate rim carrying...`（"所有盘子"）时，MJ 只在**未被遮挡的盘子**上执行——堆叠盘的盘沿被遮，图标全落到了传送带上。**图标位置不可控**，要靠构图主动把带图标的物件放进视觉重心，否则唯一承载语义的元素会待在没人看的角落。同案复盘见 [[载体默认语义反噬_v1]]。

## 外部情报（2026-07-24 正式发布，非自测）

> 来源分级：**官方**＝Midjourney 发布公告 / release notes；**三方**＝社区实测文章，仅作假设，未经本仓库验证。

### 官方

- **7/24 发布 v8.2**，主打 aesthetics / image quality / personalization。原话：图会更 "creative, bold, sophisticated, edgy and fresh"，随机低质量图的概率大幅降低。
- **6/25 Draft Mode 支持 `--sref random`** ⚠️重要：一次出 **24 张、每张一个不同的随机 sref 码**，512×512，整批约 0.4 GPU 分钟。官方口径"style space 探索快 24 倍"。
- 6/11 v8.1 转正为默认（替代 v7）；Draft Mode 于 6/16 随 v8.1 上线。
- 官方公告**未列任何参数变更**。

### 三方（假设，待验证）

- v8.2 比 8.1 更愿意留下**强对比、非对称构图、粗粝质感**。
- `--style raw` 重要性上升——是对抗 v8.2 更强风格化的主要手段。
- `--stylize` 需整体下调重新标定；`--sw` 可较 8.1 下调（style 匹配更准）；`--chaos` 较 8.1 低 10–20。

### 由此推出的工作流变更

**1. 找锚流程改写**（影响所有"先找 sref 锚再全片复用"的项目）

旧：`--sref random` 跑 4–6 次，人工挑。
新：**一次 `--draft --sref random` 出 24 张**，从中挑锚 → 记码 → 去掉 `--draft` 全质量复跑确认。样本量翻四倍，成本降一个数量级。

边界：draft 是 512×512 低质量，**只能判色调 / 构图 / 氛围，判不了细颗粒度问题**（如"一点红 vs 满屏泛红"这类颜色纪律）。这类验证必须全质量跑。

**2. 克制型项目需反向压制** ⚠️

v8.2 的"bold / edgy / 强对比"取向，对**克制、冷调、近单色、大留白**的项目是**逆风**——模型默认往"更抢眼"推，正好是这类项目要躲的方向。这类项目升 8.2 不能只改版本号，要同时：`--style raw` 保留、`--stylize` 主动压到默认（100）以下、`--sw` 下调。

首个实践：[[44_异常值]] 风格基底（系统档案影像 / 近单色 / 红色严格配给），尾参定为 `--v 8.2 --style raw --stylize 50`、`--sw 150`。`--stylize 50 vs 100` 的对比结论回填本档案第 5 条。

## 换用建议

- 写实人像项目：**直接上 v8.2**，老 prompt 可直跑试水，但入库前必须过角色卡硬锁清单（踩坑见 [[新模型试跑_硬锁清单先行_v1]]）
- 需要锁脸的多镜头项目：v8.2 质感镜头 + 锁脸镜头分工的混合策略，沿用 v8.1 档案的 A/B/C 分类法
- **克制 / 冷调 / 近单色项目**：升 8.2 要连带压 `--stylize`，不能只改版本号（见「外部情报 → 工作流变更 2」）
- **任何要锁 sref 锚的新项目**：找锚一律先走 `--draft --sref random` 大批次，别再手动跑多轮
