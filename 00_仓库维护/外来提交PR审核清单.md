# 外来提交 PR 审核清单

> 一句话律：非本人贡献者的提交，先拦在 PR 关，按本清单逐项过审——重点抓「他机路径污染、索引列错位、双链/frontmatter 规范」三类最易漏的合规偏离。

## 背景

本仓库是多贡献者仓库。核心贡献者（`Mr-Salticidae` / `Charles WANG` / `MrJumpingSpider`）为作者本人多账号，另有协作者（`Rankle2611`、`MAX0315` 等）可直接 push `main`。

2026-09-03 曾出现一次合规偏离：协作者 `Rankle2611` 归档 3 个 skill 时，索引登记出现「表格列语义错位 + 他机绝对路径（`C:\Users\1\...`）污染」。为杜绝同类问题，非本人贡献者一律改走 PR，由作者按本清单审核后合并。

## 触发时机

- 协作者提 PR 到 `main`；
- 协作者 push 到受保护分支被拦后，需走 PR；
- 作者本人直接 push 的内容，也可用本清单做自查（但不受 PR 约束）。

## 审核清单（逐项核对）

### 一、他机绝对路径污染（最高优先级，本次最痛点）

- [ ] 全库 grep 扫描 `C:\Users\`、`/home/`、`/Users/` 等**他人机器**绝对路径，确认没有混入**索引与登记类文档**（`*索引.md`、`SKILL_INDEX.md`、`README.md`）。
- [ ] 区分两类路径，处理方式不同：
  - **索引/登记处的路径** → 必须改为库内统一路径（`E:\knowledge-base\...`）或直接删（库内路径自明）。
  - **skill 原文 verbatim 归档内容**（如 `使用说明书.md` 里记录原作者部署位置）→ 保留，属来源真实性记录，不改。
- [ ] 确认「文件路径」字段若指向库内，统一用 `E:\knowledge-base\` 前缀，不得出现 `C:\Users\1` 之类。

### 二、索引表格列语义对齐

- [ ] 逐表核对：表头列名与每行单元格语义一致。常见错位：
  - 「类型」列填成用途长描述（应填简短分类，如「图片伪影修复」而非「诊断并修复鱼鳞纹、蜂窝纹…的完整工作流」）；
  - 「对应测试复盘」列填成来源路径（应填 `[[双链]]` 或「待测试」）；
  - 「版本」列填「未标注」（应统一为 `v1.0` 或如实标注，格式与其他行一致）。
- [ ] 新增行不改变表格列数，不破坏 Markdown 表格对齐。

### 三、frontmatter 与双链规范（curator 规范）

- [ ] frontmatter `---` 顶到文件第一行；`tags` 只挂**一个** `类型/xxx`（单一颜色轴），`主题/`、`来源/` 可加但不影响颜色。
- [ ] 双链 `[[]]` 内**不带 `.md` 后缀**（内核文档）；skill 存档例外——`[[skill名/SKILL.md]]` 带子路径是既有惯例，保留。
- [ ] 新内核文档必须**同时登记两处**：对应子目录索引 + 根 `README.md` 主题脉络（最易漏的一步）。
- [ ] 双链对称：新增文档链接了旧文档，旧文档「关联文档」段应补反向双链。
- [ ] 库外产物用裸路径，不塞 `[[]]`。
- [ ] 不出现虚构的双链（指向不存在的文档）。

### 四、归档归位

- [ ] 新文档归入最贴近的问题域子目录，不平铺在分类根目录。
- [ ] skill 归档放 `07_skill存档/<skill名>/`，且登记进 `SKILL_INDEX.md` 与 `07_skill存档索引.md`。

## 审核执行方式

1. **自动化前置**：PR 触发 `.github/workflows/pr-compliance-check.yml`，自动扫描「他机路径」「索引列错位」等可脚本化的项，违规即标注（`check` 失败但**不阻断合并**，作为快速告警）。
2. **人工终审**：作者本人（或桓代劳）按本清单逐项过一遍，重点看脚本查不到的语义问题（如「类型列填成用途」、双链对称性）。
3. **合并决策**：全部通过 → merge；有偏离 → 在 PR 里 comment 指出，要求协作者修正后再合。
