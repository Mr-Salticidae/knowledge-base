# 浏览器插件自动化的能力边界

> 入档:2026-06-24
> 来源:用 Claude-in-Chrome 插件把 H5 游戏《反诈柜台》发布上 itch.io、并尝试操作微信后台的实操
> 验证状态:⭐⭐ 二次印证(itch + 微信后台两处独立卡点),且与平台通则一致

---

## 一句话

浏览器插件能替你**导航、填表、点选、读页面状态**,但有三类硬边界必须由人来过:**①登录 / 验证码 / 不可逆发布、②文件上传(沙箱)、③被安全策略拦截的域名**。接活前先把"哪些插件做、哪些人做"分清楚,把人工步骤打包成清单,别假装能全自动。

---

## 三类硬边界

1. **登录态 / 验证码 / 不可逆发布**:账号密码、人机验证(CAPTCHA)、"提交审核 / 发布上线 / 接受条款"这类不可逆或面向公众的动作——插件不做也不该做,交用户本人点。
2. **文件上传 = 沙箱**:插件只能上传"会话已连接目录"里的文件;无人值守模式下"连接目录"的授权弹窗不可用 → 实际就是**让用户在原生文件框里手动选文件**。封面 / zip / 截图做好后,上传这一步默认要人。
3. **安全域名拦截**:部分后台域名被插件安全策略直接拦(实测 `mp.weixin.qq.com` 返回 "This site is not allowed")——这类站根本进不去,只能写图文步骤交用户在自己浏览器里做。

---

## 如何使用

- 接"用插件帮我发布到 X 平台"类任务:先判准入门槛(账号 / 主体 / 类目)+ 上面三类边界,产出"我做的 / 你做的"两栏清单。
- 文件类(封面 / zip / 截图)默认让用户选;最终"发布 / 提交"那一步**停下等用户确认**。
- 域名进不去就直说,给步骤,不要硬试。

## 2026-09-26 补丁:三平台投稿实测,补一条「工具上限不能倒逼降质」

> 来源:76_清月 发布,Claude in Chrome 辅助 B站 / 抖音 / 快手三个平台投稿。作者上传视频、登录并点发布,助手填其余字段、停在发布按钮前。

**三类边界这次都应验了:**

- ① 登录由作者扫码;三个平台的「发布 / 投稿」都由作者本人点。助手每个平台都停在按钮前,把已填内容列给作者审。
- ② 文件上传这次**不是沙箱问题,而是体积上限**:扩展的 file_upload 单文件上限 10MB。封面图(1–3MB)能由助手传;成片母版 13.1MB 传不了。
- ③ chatgpt.com 在应用内置浏览器里触发 Cloudflare 人机验证。**没有尝试绕过**,改用作者已登录的 Chrome。

**新增一条(⚠️首次):工具上限不能倒逼降质。质量步骤交还作者。**

撞到 10MB 上限时,助手自作主张把成片压成一个 8.9MB 的"上传版"。作者原话:「不能为了自动化而压缩视频质量」。已删掉那个文件、改由作者手动上传原版母版。

- 判据:一个步骤会影响观众看到的画质、音质或内容(成片、封面原图、音轨),工具在这一步够不着时,**把这一步交还给人**,不要改素材去迁就工具。
- 为什么容易犯:降质版能让自动化"一路绿到底",看起来像解决了问题。但画质损失在发布后无法挽回,而人手动传一个文件只要十秒。
- 同一逻辑的一般形式:工具的限制是工具的问题,不能变成作品的问题。

**两个操作细节(Claude in Chrome):**

- 扩展只能操作**它自己的标签组**里的标签页。组里的标签全关掉时组会解散,之后要重建标签组,并请作者把平台页拖进组里。
- 平台的文件框多是隐藏的 `<input type=file>`,而且一页有好几个(竖封面、横封面、视频)。先用 JS 给每个 input 标上 `aria-label` 再定位,否则会传错位置(本次抖音横封面第一次就传到了别的 input)。

- 补(同日视频号):**微前端页面(wujie)把表单放在 shadow DOM 里,扩展的元素定位看不到**。只能按坐标点击、用 JS 读回;文件要先传进主文档的临时 input,再在沙箱 iframe 的 realm 里重建 File 转交。直接转交主页面的 File 会被静默忽略。

详细的四平台字段清单与转交写法见 [[多平台同步投稿_发布页字段与浏览器辅助清单_v1]]。

## 2026-10-01 补丁:四平台投稿第二个样本,分工照做没有返工

> 来源:71_余温《瑟兰薇》角色 PV(16:9,38 秒,成片 25 MB),Claude in Chrome 辅助 B站 → 抖音 → 快手 → 小红书。

- **「工具上限不能倒逼降质」第二次照做**:开工前就定好由作者手动选视频文件,助手没有做压缩版。17:24 开工,约 18:00 四个平台都发出去了,共约 36 分钟,上传这一步没有返工。这是流程的第二个样本,不算规则的新证据,因为规则这次没有再被挑战。
- **computer use 对浏览器只给只读权限**:作者说「用 computer use 协助我发布」,但网页填表只能改走 Claude in Chrome。
- **三类边界再次应验**:
  - 登录由作者扫码。
  - 四个平台的发布按钮,都在作者确认后才点。
  - 平台协议(小红书《原创声明须知》)由作者本人勾选。
- **shadow DOM 不只出现在微前端页面**:B站评论区也在 shadow DOM 里,扩展的元素定位看不到。置顶评论要用 JS 逐层穿透 `shadowRoot`,找到菜单按钮再点。
- **点发布前把所有字段读一遍**:这次查出两种情况。
  - 一个被误点上的合集,已清空。
  - 作者自己在页面上加的话题、合集、群聊,问过作者后保留。
