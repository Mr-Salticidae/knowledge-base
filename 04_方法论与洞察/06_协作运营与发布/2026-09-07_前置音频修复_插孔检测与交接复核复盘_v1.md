# 前置音频修复：插孔检测与交接复核复盘 · v1

> 收口日期：2026-09-07。状态：前置耳机播放已恢复，作者确认左右声道正常。
> 一句话总结：**接手修复先重新量当前状态；“输出列表没有”不等于“驱动没有”，端点可用也不等于人耳已经听到。**
> 证据范围：本机单次成功案例。重启后持久性、最初触发原因与检测电路健康状态未验证。

## 结果与改动

在已安装的 Realtek Audio Console 中，点击左下角“模拟”旁齿轮，勾选 **“禁用前面板插孔检测”**。前置输出立即变为可用，Windows「系统 → 声音」将 **Realtek HD Audio 2nd output** 显示为默认输出。点击该设备属性中的“测试”，作者回答：“听到了，左右声道正常”。

本轮没有重装驱动、重置 PnP 设备、运行 SFC/DISM、卸载系统更新、修改 BIOS 或重启。系统和驱动在本轮接手前已更新；不能据此断言这些前序变化完全没有贡献，也不能把本轮成功归功于重新安装驱动。

## 当前环境与交接偏差

| 项目 | 旧交接或历史记录 | 2026-09-07 现场核验 |
|---|---|---|
| 主板 | 交接将 MS-7D90 描述为 AMD B650；历史检索曾指向 BOMBER WIFI | CIM 返回 **B760M BOMBER DDR4 (MS-7D90)**；不能只按板号猜产品变体 |
| 系统 | Windows 10 22H2 | Windows 11 专业版，版本 10.0.26200 |
| Realtek 驱动 | 6.0.8988.1（2020） | 6.0.10007.1（2026-06-23），oem31.inf |

| 驱动绑定 | 交接推断通用驱动接管、OEM 匹配失活 | 本轮绑定 Realtek 服务，INF 精确匹配 ALC897 的硬件 ID；设备问题码为 0 |
| 输出端点 | 普通输出列表仅见 Mi Monitor，写成 Realtek 端点未枚举 | Realtek 输出有注册记录，但状态为“未插入”；控制台同样没有识别插入 |

旧交接把“更新后无声”进一步解释成“累积更新破坏 OEM 驱动匹配”。**先后关系是真正的排查线索，但不足以证明该根因**。本轮不能追溯重建故障发生时的全部状态，只能确认当前绑定与旧假说不同。

交接中的“安装控制台会压低 OEM 驱动优先级”“只有下载 OEM 驱动才可行”等说法，也没有在本轮获得证据支持，不作为后续排障前提。

## 诊断转折：不存在，还是被判为未插入

检查分成三层：

1. **驱动与服务层**：Realtek 设备问题码为 0；Windows Audio、AudioEndpointBuilder、Realtek 通用服务均运行，INF 包含本机硬件 ID。
2. **端点状态层**：注册记录中的 Realtek 扬声器、2nd output 均为 `0x00000008`；作者确认耳机已经插入，仍然无声。控制台前面板插孔未亮，且“禁用前面板插孔检测”未勾选。
3. **实际播放层**：更改上述单个设置后，2nd output 变为 `0x00000001`；Windows 声音页面可选并显示默认输出；人耳确认左右测试音正常。

微软定义 `0x00000008` 为 `DEVICE_STATE_UNPLUGGED`（未插入），`0x00000001` 为 `DEVICE_STATE_ACTIVE`（可用）。因此要区分 **NOTPRESENT、DISABLED、UNPLUGGED、ACTIVE**，不能把它们统称为“驱动丢了”。注册表记录也可能残留，本案以控制台表现、状态变化和实际播放共同验证，不把单条注册记录当成唯一证据。[微软端点状态定义](https://learn.microsoft.com/en-us/windows/win32/coreaudio/device-state-xxx-constants)

| 对象 | 改动前 | 改动后 | 验证范围 |
|---|---|---|---|
| Mi Monitor | 可用 | 仍可用 | 本轮未做显示器音频试听 |
| Realtek HD Audio 2nd output | 未插入（8） | 可用（1），默认输出 | Windows 测试音左右声道正常 |
| Realtek 后置扬声器 | 未插入（8） | 仍为未插入（8） | 本轮未接后置口测试，不判定其损坏 |
| Realtek 麦克风 | 普通端点列表未出现 | 新增，状态 OK | 只验证端点出现，未做录音验收 |

## 复盘：做对了什么，哪里还可以更快

- **保留失败记录，但复核支撑它的环境。** 旧记录帮助跳过无新证据的 PnP、SFC/DISM 循环；它不能阻止读取当前型号、版本、绑定与端点状态。
- **本轮也曾受旧记录牵引。** 开始查询过历史所指的 BOMBER WIFI 支持页，随后现场型号纠正为 DDR4。更好的顺序是先读完整型号，再决定是否需要下载驱动，避免让记忆替代设备身份。
- **修正自己的问题表述。** 本轮初期也将问题描述为“没有生成端点”，深入读取后才改成“已有端点被判为未插入”。这一步改变了后续动作，重点从安装转到插孔检测。
- **一次有区分力的测试胜过重复修复。** 勾选检测绕过选项前后，记录端点状态，并在同一次操作里完成实际试听。它直接检验了当前检测路径是否阻挡播放。
- **工具成功与用户成功分开。** 控制台打开、设备状态 OK、输出列表出现，只是中间检查点；作者听到左右测试音才是本项目的功能验收。
- **功能恢复和根因查明分开。** 本例证明绕过检测可恢复当前播放，尚未区分驱动检测逻辑、前面板接线、插孔检测电路。无需为了宣称“彻底查明”继续改动已恢复的系统。

## 如何使用：同类故障的最短排查顺序

1. 插一副确认可用的耳机，并确认使用前置还是后置口。
2. 核对当前主板完整型号、系统版本、驱动绑定；按现场状态判断是否还需要交接中的安装步骤。
3. 查看声音设置和经典声音面板中的禁用、断开设备，区分“不可用”的具体状态。设备管理器的 Status=OK 不能替代端点检查。
4. 若实际已插入但系统仍报告未插入，且兼容的 Realtek 控制台提供该选项，可记录原设置后测试“禁用前面板插孔检测”。该选项的含义是**不依赖插入检测来启用端点**，不是禁用前置音频输出。
5. 核验端点出现、默认输出正确、音量合适，再播放左右声道测试音。不要在端点刚出现时宣告修复完成。
6. 若仍无声，恢复原设置或记录保留理由，再检查耳机、插孔类型和连接线路；不要把本例当成所有音频故障的统一处方。

MSI 官方排障说明同样要求检查控制台插孔识别、输出选择并交叉测试耳机；它支持这条检查思路，**并不证明本机一定属于硬件故障，也不保证所有型号都有相同选项**。[MSI 主板无声排障](https://www.msi.com/support/technical_details/MB_Audio_No_Sound)

## 收口边界与再次发生时的入口

- 本项目按“前置耳机可正常播放”收口；不继续下载驱动或进入 BIOS。
- 选项开启后，拔出耳机时端点可能仍显示可用。需要显示器出声时，手动选择对应输出。
- 恢复原设置：取消“禁用前面板插孔检测”。
- 本次未测试重启后的持久性；下次正常重启后若复发，先确认此设置与默认输出是否保留，再继续排查。未安排自动监控或后台重启。
- 历史 Store 联网处理属于前序支线；控制台能在本轮打开不等于重新验证了当时的网络归因，不计入本轮修复动作。
