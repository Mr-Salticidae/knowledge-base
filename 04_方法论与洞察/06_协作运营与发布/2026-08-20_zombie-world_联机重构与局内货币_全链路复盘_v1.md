## 四次方向被推翻

### 1. 「没有公网服务器」——错误前提裁掉两个月 ❗

见独立律档：[[约束型结论先复核律_文档写的不可能会过期_v1]]。
一句写在 README 里的约束，让所有联机设计在"怎么不用服务器"里打转两个月；
而服务器早就部署好并跑了 23 天，只是配了纯 IP + 纯 HTTP，https 页面连不了 `ws://`。

### 2. 「iOS 本地网络权限死结」——复述了一个已被推翻的猜想 ❗

同上律档实证二。结论就写在项目记忆里，没先读就下了判断。

### 3. Cloudflare 免费信令——完整做完，整套没上线

按"零成本零维护"的约束，设计并实现了 Worker + Durable Object 信令服务：
业务逻辑与平台解耦（纯函数进出）、22 条单测、本地两标签页端到端跑通、部署文档齐全。
容量与定价也查得很准（KV 免费层每天 1000 次写 = 500 局/天到顶，所以改用 DO）。

**栽在最后一公里**：`dash.cloudflare.com` 对命令行客户端返回 bot 挑战页
（`Just a moment...`），而 wrangler 的 OAuth 必须去那里换 token。
试了 4 次、3 种方式（含用浏览器扩展点授权页）都不可能成功。

→ 这是 [[可行性生死线前置律_移植先探一票否决约束_v1]] 的**第三次验证**，
且是新维度：前两次的生死线是"性能"和"权限等级"，这次是**认证链路本身**。

### 4. 「Minecraft 式局域网发现」——正确设限，不算推翻

用户要的观感在浏览器里做不到（无 UDP / 组播 / 监听端口，页面当不了服务器）。
第一时间说清楚**能力边界的物理原因**，并把问题拆成三格：

| Minecraft 的那一步 | 浏览器 |
|---|---|
| 局域网广播自己 | ❌ 做不到 |
| 客机自动列出附近的房间 | ❌ 同上 |
| **把 offer/answer 递过去** | ⚠️ **只有这格能改——鸡肋就出在这里** |
| 连上之后的数据通道 | ✅ 已经有了 |

拆格之后双方很快在"只能改中间那格"上达成一致。**这次是对的，值得保留为模式。**

## 可迁移的技术做法

### 砍数据结构前，先把「谁会读它」逐字段列出来

联机中转的快照体积直接等于带宽成本。原来的打包是"把实体的标量字段一股脑倒过去"，
于是纯服务端的 AI 状态（僵尸的绕障参数、BOSS 的五个技能冷却）也按 17 位浮点发了一遍。

改成**按类型白名单 + 定点数**，白名单照着渲染函数和客机本地逻辑逐字段对出来、
并在代码里注明"谁在读它"。同一份状态下 A/B：

| | 改前 | 改后 |
|---|---|---|
| 原始 JSON | 9135 字节 | **3263**（−64%） |
| 压缩后 | 3282 字节 | **1127**（−66%） |
| 每客机 | 80 KB/s | **28 KB/s** |

**关键纪律**：白名单而不是黑名单；砍完必须端到端实跑对账（数量、得分、抽样字段精度）——
砍漏一个字段的表现是"房主看得见客机看不见"，极难查。

### 用「同一状态下的 A/B」代替前后两次测量

第一次测瘦身效果时前后两次的敌人数不一样，得出"0% 改进"的假结论。
改成在同一帧上同时跑新旧两种打包，才拿到可信的 −64%。
**性能优化的对照必须同状态，不能同场景。**

### 反馈里的"偶尔"往往不是随机

"偶尔自动切枪，没能复现"——查下来是解锁新武器时无条件 `p.weapon = i`，
每局只在跨过连击阈值时发生几次，所以像随机。
**用户说"偶尔/没能复现"时，先找"低频但确定"的触发条件，别先假设是竞态。**
