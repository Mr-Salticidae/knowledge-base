## 已观察到的两个数据点

### 数据点 A:《花期很短，她很慢》古风作品集封面

- **任务**:雪檐少女 + 三行竖排楷书诗 + 红色"檐下"印章
- **代码版**(Claude + PIL):**6 个版本迭代 → 阳文篆书印章 + 印面分布**
- **GPT Image 2**:重画了人物五官,中文字符偶有糊字,印章偏数字感
- **赢家**:**代码版**(用户判断)

**赢的关键维度**:
- ✅ 像素级保真原图
- ✅ 中文字符精度 100%
- ✅ 篆书印章可控(印面分布 + 印泥肌理 + 边缘磨损)
- ✅ 排版精度像素级
- ✅ 可批量化复用("檐下"系列每张封面共享视觉签名)
- ❌ 唯一负项:调色"电影感"不及 GPT

### 数据点 B:《大地之上》末日纪录系列封面

- **任务**:雾霾巨城 + 有机巨构 + 伪纪录片海报美学
- **代码版**(Claude + PIL):4 个版本(文艺杂志风 → HUD 监控风 → NOROI 黑条风 → 思源宋 Heavy + 取色融入)
- **GPT Image 2**:全画面满铺 + 喷漆风化字体 + 红色副标 + 顶部"A DOCUMENTARY SERIES"
- **赢家**:**GPT Image 2**(用户判断)

**赢的关键维度**:
- ✅ 真实纹理质感(喷漆飞溅 / 龟裂 / 掉块——比算法风化更真)
- ✅ 全画面满铺(没有"切刀"的人为感)
- ✅ 红色副标的色彩对抗策略(打开三层视觉层次)
- ✅ "A DOCUMENTARY SERIES" 顶部标签的位置直觉
- ❌ 不可批量化(下次再生不会一致)

### 数据点 C:《雨里旧信》网易云音乐封面(2026-08-20)

- **任务**:已定稿人像 + 中文曲名 + 拉丁副名 + 细线,1:1 老唱片封套版式
- **GPT Image 2**:叠排出来的图**糊**(创作者判断),方案作废
- **代码版**(Claude + PIL):采用并定稿
- **赢家**:**代码版**

**赢的关键维度**:
- ✅ 像素级保真原图——**人脸一个像素没动**,这是本例的红线(那张脸连抽多轮才拿到)
- ✅ 中文字形精度 100%
- ✅ 排版坐标可控,且能**一次参数化出多版对比**供选
- ✅ 三个元素同宽对齐可**反算**(主标宽度即字宽,副名字距由公式导出),手填永远对不齐

**与假说的关系**:假说预测"需要像素级保真 + 中文字体精度 → 倾向代码",本例命中。
⚠️ 仍只是**第三个**数据点,按本档自己的纪律(第 5 个数据点起才可尝试归纳、第 10 个起才可升为经验规则),**不能当准则用**。

### 数据点 D:《右下角的池塘》B站封面(2026-09-29)

- **任务**:视频帧(超分)做底,右下角叠一个**真实的游戏界面小窗**,右上暗部两行中文标题;出 16:9 和 4:3 两个比例
- **图像模型**(LibTV Lib Image,image2image,2K):字和画面的融合感更好,但**把游戏小窗里的界面文字改写了**(森林→目标/日林,水族馆→水池塘,档案→经验,全屏→全部),副句的句号改成逗号,脸也轻微磨皮
- **代码版**(PIL):采用。借了图像模型那版"拉开字距 + 柔光、不垫底框"的排法
- **赢家**:**代码版**

**赢的关键维度**:这是一张宣传图,画面里的游戏界面是在对观众说"游戏长这样"。**界面文字被改写,等于虚假宣传**,是真实性红线,和《雨里旧信》那张"脸一个像素不能动"是同一类约束:**画面里有不许改的真实内容时,图像模型的整图重绘会顺手改掉它**。

**与假说的关系**:命中"像素级保真 → 代码"。第四个数据点,仍未到第 5 个的归纳门槛。

来源:[[2026-09-29_右下角的池塘_游戏宣传微电影_实录混剪到双语字幕发布_复盘_v1]]

### 数据点 E:《余温》瑟兰薇角色 PV 三比例封面(2026-10-01)

- **任务**:用视频里"嘘"那一帧(AI 生成的精灵角色)做底,在右侧雾林虚化处叠竖排骨白宋体"瑟兰薇"+"余温",字样与正片封面一致;出 16:9 / 4:3 / 3:4 三个比例。
  - 16:9 直接在原帧上加字。
  - 4:3 先用代码从原帧裁出底图,再加字。
  - **3:4 从横帧裁不出写字的位置**(窄裁会切掉尖耳),要向上补树冠、向下补皮甲。
- **工具**:GPT Image(经 Codex `codex exec`),**由作者指定**。每张试 2 次,留较好的一张;最后用代码居中裁到精确比例,再用 Lanczos 缩放。
- **结果**:作者「封面可以」,三张一次通过。
  - GPT 对脸有轻微重绘:更锐、皮肤质感更硬,16:9 比原帧推近约 5%,3:4 的眼型稍细。作者没提。
  - Codex 自评"不重绘、保留原帧柔和质感"两条硬标准没有完全做到。
- **赢家**:**GPT 版被采用**。**这次没有双轨**,没做代码版对照,所以只能算"GPT 可行",不能算"GPT 赢"。

**和 C、D 的对照**:C、D、E 都是"已有画面上叠字",C、D 判给了代码,E 用 GPT 也通过了。差别在于画面里有没有一个像素都不能动的真实内容:

- C 是已定稿的人像脸,D 是真实的游戏界面文字,改了就是错。
- E 是 AI 角色在视频里的一帧,轻微重绘可以容忍;而且 3:4 需要外扩,代码做不了。

**旁证(同项目,不是封面)**:片中的名片用代码排版。v1 用代码给字加了"做旧斑点"质感,被作者否:「灰色的点点看起来不舒服」;v2 改成干净字体后通过。GPT 封面上的"做旧宋体"质感却被接受了。这和下方盲区第 6 条"纹理需求 GPT 暂时领先"同向。但两者载体不同(动态视频叠层 vs 静态封面),只算弱旁证。

**与假说的关系**:第五个数据点,到了本档"可以尝试归纳"的门槛。暂时的归纳(⚠️):**叠字任务先问"画面里有没有不许改的真实内容"**。有(真人定稿脸、真实界面、品牌元素),就走代码;没有,且需要外扩或整图融合,GPT 可行。这条只有 C、D、E 三个点支撑,E 还没有对照组。

来源:[[2026-10-01_余温_见证者角色PV_立项到四平台发布_复盘_v1]]

## 暂时性假说(强调:**暂时**)

**当前线索**指向以下方向(注意:仅 2 数据点,易被新证据推翻):

| 工具 | 看似擅长的场景 |
|---|---|
| 代码版 | 需要可复用 IP 视觉签名 + 像素级保真 + 中文字体精度 + 长期一致性 |
| GPT Image 2 | 需要一次性大片美学 + 真实纹理质感 + 整图融合而非分区拼接 |

**对应到作品类型**:
- 长期 IP 系列封面(如「檐下」古风线)→ 暂时倾向代码
- 一次性海报 / 单作大片(如《大地之上》末日海报)→ 暂时倾向 GPT

---

## 还需要测试的盲区

这条线索可能在以下场景被推翻或修正:

1. **写真贴边线(《肌理》)**——需要真实摄影感的作品集,代码风化字体可能不及生图自然渲染
2. **二次元贴边线(《拾光》)**——动漫风格特征,GPT 可能更擅长抓
3. **抽象作品(《众声里的留白·二期》)**——纯氛围作品,两个工具可能都能胜任,看具体调度
4. **混合风格作品**——例如"古风 + 末日"——双方都可能崩
5. **Multi-image 串联(图集)**——代码可保证统一,GPT 难一致——但若每张都要"独立大片",可能 GPT 更合适
6. **特定纹理需求**——胶片颗粒 / 印章肌理 / 喷漆 / 老照片刮痕——目前看 GPT 暂时领先,但可代码合成也未充分测试

## 测试方法论(后续怎么验证或推翻这条假说)

每次大型创作任务:

1. **如果时间允许,双轨跑** —— 代码版 + GPT 版各做一版,记录差异
2. **数据点入档** —— 记录"任务类型 / 赢家 / 关键维度",更新本文档
3. **第 5 个数据点起,可以尝试归纳"什么任务用什么工具"的更精细规则**
4. **第 10 个数据点起,可以考虑把假说升级为"经验规则"**(但仍非"规律")

---

## 当前的实操建议(带不确定性的)

**如果是一个有 IP 延续性的系列首图**(将来要发 EP.02 / EP.03):
→ 优先尝试代码版,以建立视觉签名

**如果是一次性大片 / 单作发布**:
→ 优先尝试 GPT Image 2

**如果犹豫**:
→ **双轨跑**,把对比纳入数据点

**关键**:每次决策都同时是一次实验。**不要假设你已经知道答案**。
