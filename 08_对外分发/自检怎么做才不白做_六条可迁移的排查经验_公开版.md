# 自检怎么做才不白做：六条可迁移的排查经验

> 起因是一句很随意的话：「全项目自检一次，重点检查交互式 bug 及边缘问题」。
> 没有清单，没有范围。做完之后修了 21 项，其中 5 项是「上线就会出事」的级别。
> 这篇把过程里真正有用的六条经验抽出来——都不依赖具体技术栈，换个项目照样用。

项目背景一句话：一个线下 Prompt Battle（AI 出图比赛）用的在线对战平台，选手手机参赛、主持人大屏投屏控场。下面凡是提到「现场」，指的就是这个场景。

---

## 先说结论

**一堆做同一件事的代码里，唯一跟别人不一样的那一处，就是缺陷的藏身处。**

这轮最严重的三个问题，形状完全一致：

- 三个后台清理定时器，两个包了错误捕获，第三个没包 —— 那个没包的把整个服务进程打挂了；
- 十几个渲染函数都做了 HTML 转义，只有排行榜那两行没做 —— 那两行是能偷走管理员登录凭证的漏洞；
- 同一个卡片模板里，轮次名做了转义，紧挨着的赛事标题没做。

排查时先找异类，比逐行读代码快一个量级。人写代码时会把一批同类的写成同一个样子，**写漏的那处天然显眼**——前提是你先把「同类」枚举出来。

---

## 一、别让 AI 的复核结果直接进你的结论

这轮我用了一套多 agent 并行排查：12 个方向同时找问题，再让另一批 agent 逐条「尽力反驳」。

结果是 **46 条提案，驳回 0 条**。

这个数字本身就是警报。**对抗式复核如果一条都推不翻，多半是在附和而不是在证伪。** 我在 prompt 里写了「默认怀疑态度」「证据不足就判不成立」，没用——复核方拿到一段看起来合理的分析文字，倾向于确认，而不是真的去跑一遍。

于是最严重的几条我自己跑了一遍，**两条最严重的描述都是错的**，而且错的方向一致——比报告说的更糟：

| 报告说 | 实际是 |
|---|---|
| 页面出问题后「刷新一下就正常」 | 刷新**更糟**：接口对已结束的对局返回空，页面退回写死的演示数据，大屏上打出一个根本不存在的选手名字 |
| 数据库冲突会让「大厅接口一直报错」 | 是**整个服务进程被打挂**（全站下线，不只是大厅）；好在有自动重启兜着 |

这两条纠正**直接改变了修法**：前一条要顺手清掉页面里的假数据，后一条的止血点是那个没包错误捕获的定时器，而不是接口层。照单全收的话，两处都会修错地方。

**可抄的判据**：把复核结果的**驳回率**当可信度指标。全过或全不过都不可信，必须抽最严重的几条自己验一遍。

顺带说，同样的毛病也发生在我自己身上：写测试时凭印象写接口名和路径，挂了两条。**觉得自己知道，于是没去查**——和 AI 犯的是同一种错。

## 二、页面里的占位假数据，比空白危险得多

这一轮撞到两个实例：

- 结算页写死了「本场优胜 Mori，作品获得 68% 的投票支持」。真实数据没拿到时，它就那么留在屏幕上；
- 匹配成功页写死了两个选手名字「亚总 VS Mori」，而**全项目搜下来，没有任何一行代码填充过它**——每个匹配成功的人看到的都是这两个不存在的人。

第二个尤其说明问题：它不是逻辑错误，是「设计稿里的示例数据从来没被替换过」。静态扫描和实际操作都抓不到，是部署完之后把线上页面抓下来逐字核对才发现的。

**规矩**：页面里的占位内容必须一眼看得出是占位——破折号、空字符串、「正在读取…」都行，**就是不能是像模像样的假数据**。空白至少能看出坏了，假数据看起来一切正常。尤其当它会被投到大屏上给一屋子人看的时候。

**推论**：设计稿转代码时塞进去的示例姓名和数字，是这类问题的天然来源。交付前搜一遍设计稿里出现过的人名。

## 三、保活信号不能搭业务逻辑的便车

平台上「房间」需要定时告诉服务器「我还在」（叫心跳），不然会被当成掉线清理掉。

原来这个心跳写在「拉取房间列表」这个函数里，而这个函数只被一个每 2 秒跑一次的轮询调用。后来做了实时推送优化，加了一句「有实时连接时，轮询就不跑了」——**心跳跟着一起被停掉了**。

代码里那句优化旁边还有注释说明这是有意为之。**设计本身没错，错在心跳搭了业务轮询的便车**：做优化的人只在想「还要不要拉列表」，想不到这条路上还挂着一个保活信号。

后果是完整的一条现场故事：

> 房主开好房间等人 → 90 秒后房间被服务器悄悄关掉 → 但页面上那张卡片还在，「已等待 1 秒」的计时都冻住了 → 房主觉得卡了，按 F5 刷新 → 而刷新恰好会触发「退出房间」→ 房间彻底没了。

（实测数据：停在页面上 168 秒，全程只发出 1 次心跳，就是建房那一下。）

**规矩**：保活、心跳这类东西是独立关注点，必须有自己的生命周期，不能寄生在任何「有可能被优化掉」的循环里。判据很简单——问一句「如果有人把这个循环关了会怎样」。

## 四、「用户看不到」不叫安全

平台有个「匿名投票」：投票时界面上只显示「作品 A / 作品 B / 作品 C」，看不到作者。

但接口返回的数据里，每件作品都带着作者 ID，**同一个返回体里还有一张 ID 对昵称的对照表**。打开浏览器开发者工具的网络面板，一眼就能把每件作品对上具体的人。

同一个家族里还有：权限按钮只是被隐藏了，但接口没做校验；内容「下线」只删了界面，接口还能访问。

**通用判据**：任何以「用户看不到」为前提的安全属性——匿名、脱敏、权限——验收方式都是**绕过界面直接打接口，看它还给不给**。给了，就等于没做。

**修法上有个通用形状**：前端要那个敏感字段，往往只是为了判断「这是不是我自己的」。换成一个「是/否」的布尔值就够了，不需要把全部身份信息发出去。

## 五、服务器在反向代理后面时，「来访 IP」不再是用户

登录失败次数限制（防止别人暴力猜密码）按来访 IP 计数。

但生产环境是 Nginx 反向代理转发到本机，**这个「来访 IP」对所有外部用户永远是 127.0.0.1**——全站共用一个计数桶。

实测后果：一名选手连输错 11 次密码后，管理员用**正确**密码登录被拒、另一名选手用**正确**密码被拒、新用户注册也被拒。**现场十分钟内谁也进不来，包括主持人**——等于当场失去控场能力。

讽刺的是，Nginx 配置里**一直在传**真实 IP 的请求头，只是后端没读。配置和代码各自都「对」，接缝处没人管。

**更要紧的一层**：就算读对了真实 IP，**线下活动整个会场共用一条出口网络**——按 IP 卡死照样是全场连坐。所以这类限制必须**以账号为主维度**（严格），IP 维度只用来兜住明显的批量扫描（放宽），而且**只在真正失败时才计数**（原来是每次请求都加一，成功的登录也在吃配额）。

**可抄的两问**：任何「按来源限流」的设计，先问——① 反向代理之后，这个「来源」还代表用户吗？② 目标用户会不会成批共用同一个来源？线下活动、学校、公司网络，全都会。

## 六、方法论：怎么把「自检一次」这种模糊需求落地

这轮实际是两条腿走路，缺一条都不行：

**静态排查**（读代码找问题）擅长后端的并发、状态机、数据一致性——这些靠点界面点不出来。

**实机验证**（起一个隔离环境，真的当用户用一遍）擅长完全不同的一批：连接状态指示器永远显示「连接正常」（因为它只读了浏览器的联网标志，服务器挂了它不知道）、断网时切换页面全程无提示、后端 79 个错误码里 42 个没翻译成中文直接把英文弹给用户。

两者重叠度很低。**只做一样，会漏掉另一样的全部。**

还有三条操作纪律，回头看很值：

1. **隔离环境**：独立端口 + 临时数据库，不碰真实开发数据。收工时核对过：代码仓库干净、真实数据库最后修改时间没变。测试里注册的攻击用账号、跑废的对局，全在临时库里。
2. **先复现 → 修 → 再复现**。不是读代码觉得不对就改。每条都先把现象跑出来（拿到具体数字、日志、页面状态），改完用同一份数据再跑一遍对照。最有价值的一次是那个进程被打挂的问题：先看到接口报错，继续观察才发现进程真的退出了，拿到完整堆栈才知道止血点在哪。
3. **部署完不算完，要核对线上产物**。把线上页面抓下来逐项核对，这才发现了「亚总 VS Mori」那个从来没被填充过的假名字。

## 一页速查

| 场景 | 先问自己 |
|---|---|
| AI/工具给了你一份问题清单 | 驳回率是多少？全过就抽最严重的几条自己验 |
| 页面上有占位内容 | 它一眼能看出是占位吗？还是像真数据？ |
| 要优化掉某个定时循环 | 这条路上有没有挂着保活/心跳这类独立职责？ |
| 做了「匿名 / 隐藏 / 权限」 | 绕过界面直接打接口，它还给不给？ |
| 按 IP 做限流 | 反代之后这还是用户吗？用户会不会共用一个出口？ |
| 排查一类问题 | 先枚举「同类」，再找里面的异类 |
