## 台词：从"读错的字"到"换成高频词"

最终台词（全片.r2，whisper 六句逐字全对、顺序全对）：

| 原句（低频） | 实测读错 | 新句（高频） |
|---|---|---|
| 作品就绪 | — | 作品准备好了 |
| 全舰——启航 | "全剑" | 全体——出发！ |
| 确权完成，追踪锁定 | "主阵完成"、"确认完成" | 版权确认，全程追踪 |
| 全球发行，跃迁 | "越宴" | 全球发行——加速！ |
| 护航抵达，移交接收方 | "软交""转交" | 已经送到，请签收 |
| 收益回流 | "收一会儿" | 收益到账 |

三次尝试的对比（都是 whisper 转写，作者人耳确认了确权两次都不对）：

1. **一条.r1 / 后18.r1（原词，无提示）**：确权、跃迁、移交都读歪。
2. **前15.r1（原词 + 拼音读音提示）**：跃迁、移交读对；**确权仍读成"确认"**；另外"收益回流"跑到"护航抵达"前面说，顺序和提示词相反。
3. **全片.r2（换高频词，不再需要读音提示）**：六句全对、顺序全对，切点 2.958 / 5.500 / 10.000 / 15.000 / 22.417。

- 作者原话："「确权」念得不对，而且全篇节奏还是有问题，我觉得我们直接把这段词改为好读的词，参考知识库中的资料"——指向 [[低频退化与频率定律_v1]]。
- 品牌口径没丢：版权确认＝内容确权，全程追踪＝监测追踪，全球发行原词，收益到账＝交易变现。

## 作者的纠偏（按时间）

1. "改 prompt，字幕是对的，让视频重新出"——助手先前在改字幕，方向错了：问题在画面里念错，不在字幕。
2. "直出一条完整的替换前面，避免前后不一致，不方便剪辑"——否掉"前10＋镜4"两条分拍方案。
3. "确权念得不对……改为好读的词……直出全片"——否掉"读音提示"补丁，从词频上解决。
4. "最后那里宣传的位置有些不妥，不够影视级"→"不要用墨黑底色，纯黑色更高级"——片尾从静态字卡改成影视式 end tag。
5. 封面："完全错误的，你这样出来的封面与原视频差异太大了，参考都没放全"→"直接选一张剧照作为封面底图，然后用 chatgpt image 2.5 去排版"→"封面不要有营销信息"→"不要用中文标题了，太 low 了，直接英文大字，模仿沙丘的海报风格"→"从 0 重新生图"。最终：20.6 秒剧照为底，GPT Image 2.5 只做排版，只有 "ESCORT" 一个词。

## 助手侧的误判（记下来，下次不再犯）

1. **把"读音提示"当成解法**：写拼音只修好了两个词，确权仍错，还在提示词里写"不要读成'软交'"这种会给模型递错误读法的反例（第一时间删掉了，但思路本身是补丁）。正解是换词，见下条方法论。
2. **分段重拍**：一直在"保留好的那段、只重拍坏的那段"的思路里打转（后13、后18、前10、镜4、前15），每次拼接都带来新的不一致（能量断档、台词顺序、构图）。作者一句"直出一条"解决。
3. **封面从零生成**：第一次让 GPT Image 2.5 凭一张猫图重画整个场景，出来的外星人变成长发精灵——与片子不符、参考不全。封面应以**剧照为底**，AI 只负责排版。
4. **自动化事故**：给 Lexical 编辑器清空时用了 Ctrl+A / Delete，焦点落在画布上，**误删了一个视频节点**（立即 Ctrl+Z 恢复）。之后脚本先确认焦点在编辑器里再全选。
5. **节奏拖沓**：浏览器自动化每步都要截图确认，主机内存长期低于 2 GB，会话被杀一次；作者多次问"为什么这么慢"，最后视频号改为作者自己提交。

## 方法论沉淀

### 视频模型同期对白：低频专有词读错，换高频说法，不靠读音提示

**核心**：Seedance 同期对白里的专有词（确权、跃迁、移交接收方）会稳定读歪；拼音提示只能救一部分，换成语义相同的高频口语说法才全对。

**来源**：本项目三次对白生成的前后对比（见上表）。

**验证状态**：⚠️ 首次发现（一个项目、三条生成；未做严格单变量对照——全片.r2 同时换了词和整条结构）。与 [[低频退化与频率定律_v1]] 的"写得更高频优先于写得更复杂"同向，是该理论在**视频模型 TTS** 上的第一个实例。

**操作规则**：
1. 写对白时先过一遍"低频词清单"：行业术语、四字公文腔、少见搭配。能换就换成口语高频说法，保证品牌语义映射还在。
2. 实在不能换的词，读音提示只写正确读法（拼音＋常见组词），**不要写"不要读成 X"**。
3. 生成后用 ASR 逐句核对；ASR 听歪的词仍以人耳为准。

**反例/边界**：品牌名、产品名这类必须原样出现的词不能换，只能靠提示和多抽几条。

### 封面以剧照为底，AI 只排版

**核心**：作品封面要和片子一致，底图直接用成片剧照；图像模型只负责裁切、延展、调色和标题排版。

**来源**：GPT Image 2.5 凭单张猫图重画整个场景，外星指挥官变成长发精灵，作者判"完全错误"。

**验证状态**：⚠️ 首次发现。与 [[2026-08-20_雨里旧信_东方美人封面四轮复盘_v1]] 的"底图定构图，先出图再排版"同向。

**操作规则**：
1. 先在成片里抽一排候选帧（至少覆盖揭晓、主角近景、大场面），挑主体齐全的那张。
2. 提示词第一条写死"原样保留画面里的一切，不要重绘"。
3. 标题和营销信息按作者口味定：本片封面不放营销信息、不放中文，只有英文片名。

### 品牌片片尾：渐黑 + 纯黑底 + 分层淡入

**核心**：品牌定版用影视片尾做法——末镜渐黑、纯黑底、Logo / 标语 / 说明三层错开淡入、最后一帧停在完整定版上；不要硬切到一整张字卡。

**来源**：作者两次纠偏（"不够影视级"、"纯黑色更高级"）。参考 84《那道题还亮着》的末镜渐黑做法。

**验证状态**：⚠️ 首次（作为品牌片 end tag）；末镜渐黑在 84 用过一次，算同向第二例。

**操作规则**：说明性文字（平台定位）放底部小字，不和主标语抢；赛事要求"准确介绍平台定位"时用主办方原话。

## 下次改进

- 一开始就按"一条直出整片"规划，预算按一条 28–30 秒 × 2–3 次抽卡来留（本次一条约 5.1 万积分）。
- 写对白前先做低频词替换，再进提示词。
- 封面、片尾这类对外包装，先问作者参照（他这次指了 84 和《沙丘》），再动手。
- 浏览器自动化：内存紧张时先做不需要浏览器的工作；Lexical / 画布类页面全选前先确认焦点。
