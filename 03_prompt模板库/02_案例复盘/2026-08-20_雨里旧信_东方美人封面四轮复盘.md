## 一、最贵的一次教训：第一版 prompt 是凭空写的

R1 跑出**白人脸**。根因两条，都属于"库里有答案却没查"：

| 根因 | 库里躺着的答案 |
|---|---|
| 通篇没写族裔（`almond-shaped eyes` 等中性词默认落在白人脸上） | [[东方美人五官堆叠基础句]]（⭐⭐，纯文字即可锁定复古东方美人原型） |
| 把 `pin-up / calendar girl` 塞进 `--no`，关掉了唯一能给年代感的机制 | [[AI甜妹脸vs复古东方美人]]（默认落点=老月份牌女郎=1940s 老上海） |
| `--no` 写 30 词 | [[负面词计入prompt浓度_v1]] |
| 计划给"避视"镜头挂 oref | [[主体不看镜头律]] 补充条款：避视镜头一律 oref-off |

**查完库重构，一轮就修好。** 绕的那一整轮完全可以避免。

> 行动清单第一条：**写人物 prompt 前先搜库里的五官堆叠词块和同构案例**，别凭空写。

本案还找到一个几乎同构的父本：[[2026-06-13_露背回眸东方美人_chiaroscuro胶片人像复盘]]（东亚女性 + 头转向窗外 + 不看镜头 + 戏剧光），结构与本封面高度重合，可直接换皮。

## 二、方法论沉淀

### 1. 默认落点的资产负债判断 ⚠️ 已独立成档

见 [[默认落点的资产负债判断_v1]]。给 [[获奖图复盘方法论合集_活合集]] 第 40 条「负面词的预防式接种」⭐⭐ 划边界：**接种之前先分类，别把资产当负债压掉**。

---

### 2. 光影轴的可操作项是三件：光位、头位、遮挡 ⚠️（含近似受控对照）

**核心**：[[不够帅是年龄轴不是颜系轴_v1]] 把光影轴写成"改光位与对比"。本案观察到**头位与碎发遮挡和光位是同一件事**——三者共同决定阴影落在骨骼的哪个面上。

**来源**：创作者反馈"骨相和五官不够惊艳"。按四轴分轴判定主因在光影轴，随后的出图构成一次近似受控对照：

| | R2 定妆照（骨相平） | R3 采用图（骨相立） |
|---|---|---|
| 五官词块 | — | **完全相同，一个字没改** |
| 骨相词 | 无 | **仍然没有** |
| 光 | `even soft frontal studio light, no strong shadows` | 侧向光，明暗过渡落在颧骨与下颌 |
| 头位 | 正面直立、下巴平 | 头微侧、下巴微收、从睫毛下方看镜头 |
| 碎发 | 规整 | 斜掠过脸颊并在颊上投影 |

**五官词块从头到尾没动，骨相的有无完全由光位 + 头位决定。**

这正面支持了原档的核心主张——"不够美"的第一反应是加骨相（颜系轴），但真实病灶常在光影轴；**若当时按直觉堆眉骨 / 深眼窝 / 锐利下颌，大概率跑成"凶"**（原档男主 V2 就是这么翻的）。

**操作规则**：

1. 收到"不够美 / 不够惊艳"，先分轴，不要直接加骨相词。
2. 判定在光影轴时，**三件一起调**：光位（写落点，如 `across her cheekbone and jaw`）、头位（侧转 / 下巴角度 / 视线高度）、遮挡（碎发投影）。
3. 正面直立 + 平光 = 没有任何一处阴影交代骨骼起伏，这是"平"的典型成因。

**反例 / 边界**：**定妆照 / 服饰参考图必须用平光**（要看清领型、盘扣、开衩），那时"平"是正确的。两种用途的图不要混为一谈——本案的 R2 就是刻意的平光，它没错，错的是我拿它去判断"骨相够不够"。

**验证状态**：⚠️ 首次发现，单项目。对照不严格（R3 是连抽 roll 出来的，非刻意控制变量）。

---

### 3. 一致性校验位要挑模型画得稳的特征 ⚠️

**核心**：给角色设"跨图校验位"是对的，但要挑**模型画得稳**的特征，不是挑**你验起来方便**的特征。

**来源**：本案给角色设了"左眼下一颗小痣"当校验位——二值化、可验证，验起来极方便（不用判断"像不像"这种主观问题，只看有没有、位置对不对）。R1 实测**痣落在眉间**。MJ 对点状小细节的位置控制本来就弱，这个词既没起到校验作用，还在跟五官七槽抢注意力预算。改用发型分缝方向 + 领型。

**操作规则**：

1. 校验位优先选**体积大、结构性强**的特征：发型分缝方向、领型、轮廓、色块。
2. 小痣 / 疤 / 单颗饰品这类**点状**特征，位置控不住，不要指望。
3. 校验位也占 prompt 预算，只设一到两个。

**反例 / 边界**：若用 oref / personalize 锁脸，点状特征可能被参考图带住，本条不适用。与 [[装扮签名vs五官精度]] 同向——**能被语言精确传递的才锁得住**，点状位置不在此列。

**验证状态**：⚠️ 首次发现，单案例。

---

### 4. 题眼可以搬家，不必压在画面上 ⚠️

**核心**：当画面素材与题眼冲突、而素材本身是**稀缺 / 难复现**的资产时，把题眼交给标题 / 简介 / 后续内容承载，比重绘素材去迁就题眼更划算。

**来源**：封面原计划靠画面交代题眼 `Still unread`（她拿着信却看别处 —— 一个"事件"而非"状态"）。最终选定的人像是一张**看镜头、无信、无雨窗**的肖像。为了加信去重绘手部和背景，很可能把连抽多轮才拿到的脸弄坏。改为：题眼交给曲名 + 主创说 + 后续 MV。

**操作规则**：

1. 先问"这张素材是不是稀缺 / 难复现的"。是 → 不重绘。
2. 盘点题眼还能落在哪：标题、副名、简介、置顶评论、后续内容。
3. **明确记录这次放弃了什么**，不要含糊成"这样也挺好"。

**反例 / 边界**：**闪电战 / 比赛不适用**——那里只有一张图这一个触点，题眼无处可搬（见 [[闪电战冷读者校准律_v1]]：观众只有 0.5 秒，没有简介可读）。本条只适用于有多个触点的发布场景（音乐平台、图文笔记、系列内容）。

**验证状态**：⚠️ 首次发现，单案例，**且尚无发布数据检验这个取舍是否正确**。

---

### 5. 底图字位必须实测，不能目测 ⚠️

**核心**：叠字前跑**亮度网格 + 候选字框扫描**，用 std 找干净框。别用眼睛判"哪边看起来空"。

**来源**：同一个错误在本案犯了两次——先目测判"标题放左侧"，换素材后又目测判"右侧"。实测才确认是**左上灯光区**：

```text
候选字框扫描（找 std 最低的框）
  x60-460  / y150-380    L=242.7  std=18.7  ✅ 唯一干净框
  x60-500  / y120-420    L=231.9  std=34.3  BUSY
  x40-300  / y500-1100   L=179.8  std=27.0  BUSY
  x60-460  / y1450-1750  L=156.4  std=28.1  BUSY
```

人眼对"哪边看起来空"的判断会被主体位置的印象带偏，**头发吹散、灯光晕开这类东西尤其骗人**。

**操作步骤**：

```python
# 1. 8x8 亮度网格，看明暗分布
# 2. 暗部重心 → 主体偏哪边 → 文字放对角侧（封面对角平衡构图律）
# 3. 候选字框扫描：算每框 mean + std，取 std 最低的
# 4. 落区亮度决定字色：亮底→深字+柔投影；暗底/杂底→深字+浅光晕
```

⚠️ 第 4 步本案也踩了一次：给 L=243 的**亮底**用了浅色阴影——那是**暗底**的浅光晕配方。两个配方不能张冠李戴，见 [[代码排版小红书封面工作流_v1]] 的判据。

**反例 / 边界**：底图是纯色 / 大面积单调背景时，目测足够，不必跑。

**验证状态**：⚠️ 首次发现（本案栽两次仍属同一项目，不构成二次验证）。

## 四、下次同类任务行动清单

1. 写人物 prompt 前，**先搜库**里的五官堆叠词块和同构案例。
2. **写人必须写族裔**（`east asian woman`，不写 `chinese girl`，见 [[MJ审核避雷词表]]）。
3. `--no` 每个词过一遍资产 / 负债判断（[[默认落点的资产负债判断_v1]]）。
4. 收到"不够美"先分轴，默认先查光影轴和年龄轴，**颜系轴最后动且一次只加一个词**。
5. 叠字前跑亮度网格 + 字框扫描，别目测。
6. **定妆照用平光（验形制），正片用侧光（雕骨相）**，两种用途不要混。
7. 成品出来当天建档，哪怕只写三行。
